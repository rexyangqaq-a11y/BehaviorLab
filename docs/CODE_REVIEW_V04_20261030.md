## 3. 发现与处理建议

优先级定义：P1 优先修复，影响并发输入／可靠性边界；P2 近期维护，影响证据或长任务可用性；P3 可维护性改进。位置按函数给出，行号随注释与整理变化。

### R01 · P1 · 输入锁没有覆盖仍存活的 worker

- 位置：`src/phone-lab.mjs` 的 `acquire`、`start`；对照 `src/device-lease.mjs` 的 `registerWorker` 与 `assertDeviceLease`。
- 触发：原父进程结束，但其 worker 或在途设备操作尚未确认停止；另一服务开始新的输入活动。
- 依据：输入锁只保存并检查父 PID，不登记 worker；旧父 PID 不存活时删除锁。视频与 HiLog 使用较完整租约，不表示输入路径也已使用。
- 合成复现：锁中父 PID 不存在、诊断 worker PID 为当前活进程时，`acquire` 仍授予新输入锁。实际生成的输入锁甚至不含该 worker 字段。本轮没有制造真正的 Windows 手机孤儿进程，也未实测竞态时长；确认的是代码缺少检查及文件层现象。
- 风险：父进程意外退出后可能在旧输入仍未收尾时发起新输入；具体设备后果未实测。
- 建议：输入统一使用带 worker 身份的租约，派发时登记，设备发送边界校验所有权，释放须核对 worker 结束；不能靠删锁重启。PID 复用与旧格式需保守兼容。
- 验收：活父、死父活 worker、双方死亡、guard 竞争、worker 退出窗口及旧格式分别验证；未确认释放不得新输入。再做有明确范围的系统级验证。
- 原审查轮：补注释与复现，未修复；后续状态：已完成本地实现与离线验证，详见第6节；原基线复现记录保留。

### R02 · P2 · 轨迹损坏行被静默丢弃

- 位置：`PhoneLab.snapshot`，由 `processSnapshot`、`asset`、`review` 等调用。
- 触发：`events.jsonl` 有截断或非法 JSON；读取错误同样可能被空 catch 隐藏。
- 合成复现：一条合法事件加一条损坏事件，返回只有合法事件，没有损坏标志。调用方无法区分“本来就没有这条事件”和“读取时丢失”。
- 风险：回放／导出呈现不完整轨迹但缺少显式告警，审核依据可能受影响；不是已经证明手机执行结果被篡改。
- 建议：统一账本解析，保留损坏行编号与诊断；区分活跃追加中的未完成尾行与已关闭文件损坏。稳定损坏进入完整性异常，关键证据缺失时禁止直接通过。
- 验收：空文件、合法追加、截断尾行、内部坏行、不可读文件、缺图与哈希错误；页面、JSON、审核与导出口径一致。
- 原审查轮：补注释与复现，未修复；后续状态：已完成本地实现与离线验证，详见第6节；原基线复现记录保留。

### R03 · P2 · 游标接口仍先全量读取长轨迹

- 位置：`PhoneLab.snapshot`／`processSnapshot`／`asset`；`gui-trial-transport.mjs` 的响应全文读取。
- 依据：轨迹同步读取整文件、拆行及解析后才过滤 `after`，每次图片查找也可能重读；模型响应先 clone 后全文读取。新任务默认不限额，日志增长时成本随历史增加。
- 影响：事件循环阻塞与内存压力随长任务增长；本轮未做内存／时延基准，不能声称已实测 OOM。
- 建议：事件索引或偏移读取、独立资产索引、后端分页、响应大小约束与可解释的拒绝记录。取消不能丢掉已经发送请求的用量未知状态。
- 验收：长合成轨迹反复增量读取，不丢／重事件；分别测耗时与内存，明确支持规模。

### R04 · P3 · 关键应用服务与网页存在压缩式控制流

- 位置：`phone-lab.mjs`、`web/phone-lab.mjs`、`web/workspace.mjs`，部分 tests／scripts。
- 依据：多条语句、分支、资源收尾与模板集中在同一行；`PhoneLab` 同时管理任务、起点、批次、审核、导出、视频和日志。
- 建议：先按稳定职责提取用例／查询和视图函数，一次整理一个区域，行为修复与格式变化分开。不要只增加注释而保留难以核对的控制流，也不要无关全仓格式化。
- 验收：每次拆分保持现有 API、持久格式、状态和取消行为；异常路径保留针对性测试。

### R05 · P3 · 核心依赖指向脚本和展示目录

- 依据：静态扫描5处：设备／证据／定位恢复 → `scripts/hdc-device-baseline.mjs`；PhoneLab → `web/phone-test-plan.mjs`；视频 → `web/phone-video-protocol.mjs`。
- 影响：工具与展示文件不容易由不同开发者独立改动，打包也需隐式知道这些跨目录依赖。
- 建议：纯图像尺寸与共用协议移入明确的公共模块，脚本／网页／核心反向引用；保持旧入口兼容。当前共享纯函数不等于存在运行缺陷，不能为目录整齐盲目重写。

### R06 · P3 · 缺少可执行的统一维护门禁

- 依据：`package.json` 提供测试与运行命令，未提供已配置的 formatter／lint／文档链接／依赖边界检查；部分空 catch 将读取失败与不存在合并。
- 建议：先选择最小约定与渐进检查范围，再增加团队认可的自动工具；区分允许忽略的诊断与必须上抛的业务／证据错误。
- 验收：新改动有可复现检查命令；不能通过屏蔽既有错误一次性“全绿”。

### R07 · P2 · 使用与协作材料互相矛盾

- 依据：整理前 README 堆叠 preview.10–14 的“当前版本”；部署／使用正文仍引用旧版本和15次默认请求；贡献指南仍说“最终框架未确认”。
- 本轮处理：重写当前入口，增加 PRD／架构／文档规范，明确默认不限额、三框架保留、真实与 Mock 边界；历史仍由 Git 与原发布记录追溯，**本项文档已修正**。
