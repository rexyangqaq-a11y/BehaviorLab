## 已确认，按此实现职责边界

| 需求 | 阶段 A 对应实现 |
|---|---|
| 只产上游行为数据，不实现记忆引擎 | 持久化事实与有限近期实际列表，无记忆提取/检索 |
| 简单固定人设、用户上下文独立 | 原要求与人设分别保存；复合外键；模型调用上下文只取当前用户 |
| 上层生成每日计划与每项活动后的调整 | `planner.plan/adjust`；调度器没有行为生成规则 |
| 下层理解页面与逐步操作 | 保留执行/恢复/记录协议；当前只是 Mock，下层真实方案待对齐 |
| 计划与实际、虚拟与真实时间、原文与加工文本分离 | 独立表和导出字段；原图与原始描述不被加工覆盖 |
| 活动按用户长周期连续执行，结果落盘后再反馈 | 用户外循环；结果提交后调用上层；中断后先补反馈 |
| 执行与逐图描述独立推进，活动内图像有序 | 结果终态后才进入描述队列；与下一活动重叠 |
| 每张图像采集留存、来源可追溯 | 文件资产、哈希、动作关联、截图阶段、处理历史 |
| 离线检查不自动重规划 | 检查只读来源并输出报告 |
| 行为不能由手写概率代替 Agent 自主选择 | Mock 仅作确定性工程夹具，不用于行为效果结论 |

## 可替换工程默认值

| 选择 | 理由与范围 |
|---|---|
| Node.js 24 + SQLite + 文件 | 当前可用，无需安装；少量用户单机足够；不是技术栈硬要求 |
| ESM JavaScript + JSDoc + 运行时校验 | 不依赖本机缺失的 npm/编译器；模块边界集中定义 |
| 一份数据库对应一个 Run | 简化事务、备份和恢复；不提供多机/跨 Run 真机调度 |
| 一个执行 worker + 一个描述 worker | 同一进程异步重叠，也可分开命令运行；后续吞吐再实测 |
| 近期实际列表最多 5 项 | 有界上下文，可配置；不代表研究上足够 |
| 描述最多尝试 3 次 | 包括进程中断占用的尝试；失败项显式补跑，避免无界调用 |
| JSONL + JSON 元数据 | 易检查、重建、对接研究工具；最终消费格式未定 |
| 本地虚拟活动时间 + IANA 时区 + 步骤序号 | 不擅自定义步骤精确虚拟秒数；跨夏令时绝对时刻转换尚未实现 |
| before/after/observation + step/capture index | 显式截图关联，支持一个动作多张图；真实 hipyum 的时序语义仍需确认 |
| 流水线状态与内容质量分离 | partial/blocked 可是已结束事实；自然性不能从代码测试推出 |

示例的用户数、日期、APP 名、活动时段、对象数量和失败情景均是 Mock 验证夹具，不是业务要求，更不是实际 APP 清单。

## 需要逐步讨论的关键点

下一轮先聚焦下层：优先复用已有页面理解与决策代码（如提供）；否则讨论以观察→模型决策→校验动作→调用 hipyum→保存结果构成的最小循环。只有操作 API 时，页面理解、停止判断、对象计数、失败处理和不确定动作恢复仍需要实现。暂不比较一整套长期算法方案。

真实闭环后再讨论：结果摘要是否支撑调整、近期窗口是否足够、固定人设能否产生稳定但不机械的活动、共享账号是否造成难以接受的环境串扰。每一项用实际样本和证据判断。
