## 3. v0.4：开源下层 Agent 选型与最小验证

本节保留早期制定时的要求与调研记录；当前v0.4已按约定范围交接，事实以文件顶部与CURRENT_STATUS为准。

这是下一轮主要开发任务。既有方案中的六项职责作为检查维度：子任务规划、页面观察与定位、动作选择与检查、手机接口操作、操作结果核对、进度更新与结束判断。它们不要求六个独立模型或固定六次调用。

v0.4 已进入范围讨论，见[GUI 部署、手机控制与测试需求讨论稿](V04_REQUIREMENTS_DISCUSSION.md)。用户本轮确认控制路径暂未限定，先比较框架原生 SDK 与 hipyum 两条路线；具体选型未定，不将 hipyum 设为所有候选试验的必经路径。

设备条件进一步明确为鸿蒙 NEXT、拟用鸿蒙 6 或 7、可连接 Windows 并允许调试；首测包含系统 APP 与部分常用 APP。用户要求先提供更广的框架、测试集和分数资料，再由用户决策。当前进展见[开源 GUI 框架与评测选型资料](V04_GUI_FRAMEWORK_SELECTION.md)，候选没有锁定。

### 3.1 收敛候选与技术路线

下表保留最初的四项候选依据；最新候选全景、鸿蒙路径、公开成绩与推荐以[选型资料](V04_GUI_FRAMEWORK_SELECTION.md)为准，已扩大到 MobiAgent、Mobilerun、ARTEMIS、Minitap、FinalRun、UI-Venus、MAI-UI 等。先提供比较与建议，由用户决策后收敛实际试验组合；不要求安装所有框架。

| 候选 | 纳入的依据 | 本项目必须补测的问题 |
|---|---|---|
| [Open-AutoGLM](https://github.com/zai-org/Open-AutoGLM) | 官方提供 PhoneAgent 和[单步 step 接口](https://github.com/zai-org/Open-AutoGLM/blob/main/phone_agent/agent.py)，可以作为最小手机循环的候选 | 配套模型动作协议与可用服务是否匹配；能否在动作发送前记录；工具是否能替换为 hipyum；对象量和恢复需要补什么 |
| [Mobile-Agent](https://github.com/X-PLUG/MobileAgent) | 官方项目包含多个具体版本；既有方案参考 v3 的规划/执行等分工 | 选定具体目录、版本与模型，不能把不同版本能力混用；检查控制接口、状态、调用开销和改造量 |
| [AppAgentX](https://appagentx.github.io/) | 作者项目把重复轨迹与操作复用作为研究方向，适合作为复用路线候选 | 是否适合先不建经验库的基础任务；页面变化后的退出、轨迹质量、用户信息隔离和维护成本 |
| [Midscene.js](https://github.com/web-infra-dev/midscene) / 补充项 | [官方自定义接口](https://midscenejs.com/integrate-with-any-interface)允许提供截图、尺寸与动作空间 | Node 接入成本是否更低；能否捕获每次操作前后证据及中断状态；自然语言任务执行是否满足活动完成判断 |

以上是 2026-10-20 资料核对阶段的候选依据。后续已隔离安装 Midscene 鸿蒙 SDK 1.16.0，并验证实际 SDK 动作入口 + 工具替身的记录契约，见[预览交付](V04_GUI_LAB.md)；**仍未运行真实模型/设备循环或选定胜者**。优缺点以同批任务实际结果补齐。进入真实试验时固定上游/发布包版本、依赖、模型与设备环境；代码、模型权重、附带工具的许可证分别核对。

统一比较：规划、观察、执行、核对、信息复用，以及设备适配、模型兼容、Windows 运行、步骤/截图可见性、停止与恢复、依赖、时延/调用成本。公开评测和项目演示不是本项目兼容或成功率证明。AndroidWorld 等评测作为方法参考，商业 APP 需要自己的验收用例。

### 3.2 必须交付的特性

1. **最小 runner 与对应测试调试界面**：支持本版单活动验证、运行控制与证据查看；具体用例和页面在 v0.4 开发时设计落实，复用现有记录语义，不先建设完整插件平台。
2. **动作与证据接入试验**：动作前可落意图，动作后可取真实返回与全部观察图；只拿到最终一段“完成”文本的黑盒接口不满足接入要求。
3. **环境诊断**：说明可用设备、截图能力、文本/图像模型接口、依赖与缺失项。若胜出框架是 Python，优先评估独立 worker/本机服务桥接，主系统继续复用 Node + SQLite；不为此重写整个项目。
4. **任务与结果对比**：至少覆盖基础浏览、对象条件/数量、无结果/停滞、工具超时或模型异常这几类问题；记录完成证据、失败原因、步骤、调用数和耗时。状态变更类操作只纳入已允许的任务范围。
5. **配置策略与推荐**：保留当前三框架和模型接口，由用户选择组合，提供默认推荐及证据、缺口和改造范围。此策略已于2026-10-23确认，不再要求唯一主框架；失败样本同样交付，推荐不覆盖用户配置。

测试范围补充：按用户要求纳入另一对话的全部[框架实现比较](V04_GUI_IMPLEMENTATION_COMPARISON.md)，对应[15 维度、31 项验收用例](V04_FRAMEWORK_TEST_CASES.md)已接入本版验证台。各层记忆、跨调用状态、百对象长活动和总接入成本单列；五类实现/适配状态与测试结果分开。清单不等于真实通过，不能因测试定义齐全而记正式 v0.4 完成，也不默认批量消耗模型用量。

### 3.3 完成门槛与限制

正式 v0.4 需至少一个候选在实际设备/可操作环境与真实模型条件下跑通基础活动，并交付完整轨迹及可复现启动方法。候选对照任务数量和重复次数在试验前按预算确定；单次成功不代表成功率结论。

若设备、模型或 hipyum 文档暂缺，仍可完成源码比较、接口试验、故障夹具和离线轨迹回放，发布 v0.4-preview 并标清 Mock/未验证项，不能将其记为真机验证完成。目标鸿蒙优先核对 HDC 路径；Android ADB 对照试验不能当作 NEXT 兼容或 hipyum 已适配，正式工具路径需在 v0.5 前明确。

本版可做支持试验的最少装配与状态修复，但不把完整通用服务配置中心、真实上层规划或行为库作为开始试验的前提。

## 4. v0.5：把所选下层接入任务工作台

本版接入的是下层执行能力，活动由现有任务／手工或Mock计划输入，未来由真实上层产生。商品浏览案例用于验收条件核对、去重和恢复；不得将商品、APP、关键词、2件目标或从桌面到详情的操作序列固化进调度器／通用执行器。不同活动按自身完成条件和已支持能力运行；通用输入不等于已经支持任意APP或任意任务。

**特性输出**：

- 将用户所选框架包在 `executor.execute/recover` 后，保留 `recorder.beginStep/capture/finishStep`；模型与手机工具各自有来源，活动内容来自冻结输入。
- 根据选型实现 Web/worker/CLI 所需的统一装配、服务配置和组合来源，不再到处直接构造 Mock。历史 Mock Run 默认仍可恢复，失配时显式报错。
- 沿用已具证据的HDC工具路线；hipyum准确契约仍待资料，不作为接入前置阻塞。工具路径变化时更新边界与证据，不隐式换掉。设备全局排他先于跨 Run 真机操作，账号会话单独标识。
- 在现有任务详情中增加单活动调试：当前子任务、观察/截图、动作与预期效果、实际完成量、证据、结束原因；仍保持用户库/仿真任务/系统设置三个主入口。
- 保存最小活动工作状态和对象证据，支持基础多对象/条件任务；步数、无进展、耗时有界。未知字段不补写，重复对象不按多次点击累加。
- 展示执行、描述、导出等各阶段状态，阶段失败不被总体完成标签遮盖。动作效果不明时重新观察或进入 `needs_attention`，自动恢复能力以实际验证范围为准。

**验收**：同一任务可用手工/Mock上层计划派发真实活动并保存结果。目标2个对象、实际只核实1个且无未决状态时，记录实际1及partial；重复打开不增加计数。争用设备、无进展、中断与服务异常均有结果和证据。效果不明先自动核对与有界恢复，仍不能可靠继续才needs_attention。

当前用户暂停真实手机与模型，先交付离线阶段；离线通过不能记完整真实接入通过。最新商品案例口径为目标2／已核实1且无未决状态时partial，自动核对与有界恢复优先，解决不了才needs_attention；见[需求基线](V05_REQUIREMENTS_CLARIFICATION.md)。增加参数变化和非商品活动契约用例，证明案例未被固化，不把它计为额外真实APP兼容成绩。

**交付**：可运行主系统、所选框架接入组件、任务内调试页面、示例/故障轨迹、配置与启动说明、数据迁移和回归报告。存档描述和上层内容仍可 Mock，界面/导出逐模块标明，不能称整条真实闭环。

## 5. v0.6：真实用户生成与上层规划

**特性输出**：真实人设候选生成、条件检查/审核与原稿保存；按固定用户、当前虚拟日与有限近期实际生成计划；活动后决定保持或局部调整；计划/提示/模型配置版本与每次调用可查看。

继续复用现有调度与用户库。程序校验日期、APP、数量和用户边界，不补写行为；空日计划合法；错误输出以有界纠正或明确失败处理，不能静默切 Mock。活动结果先提交，调整决定后提交，再推进下一活动。

**验收**：用户原始条件、模型原稿、审核值与历史任务快照分离；不同用户上下文不串。未完成活动可局部修改，完成事实不回写。模型超时、结构错误、结果后反馈前中断均有恢复证据。

**交付**：真实人设/规划适配器，系统设置中的模型角色绑定，用户与任务页面的真实调用示例，异常回归及初步用户差异观察。存档描述尚未接入时继续标明；不宣称已证明长期行为自然。

## 6. v0.7：存档 VLM 与第一份完整真实样本

**特性输出**：真实截图单图描述、提示与预处理版本、原始响应/观察文字、描述尝试历史、端/主机/云部署来源、按序补跑与导出格式。

先选符合现有服务与数据出域限制的部署基线，再用相同截图比较手机端、采集主机本地与云端可行性。端云选择不在计划中预定结论；必要加工文本仍另存且按已明确的授权规则实施。

**验收**：执行与逐图描述分别推进；同活动图像不乱序。描述失败只补已有图，不重采活动；成功原文不覆盖。不把任务目标、模型执行摘要或一次页面出现写成已证明的用户偏好。来源和缺失状态在任务页面与导出一致。

本版首次交付一用户、一 APP、短活动至一天的完整样本：真实上层规划、真实手机操作和原图、实际结果与调整、真实存档 VLM 原文、JSONL/元数据及资产校验。任何一段仍是 Mock，就交付对应的组合验证，不宣称全链路真实。

**交付**：VLM 组件、来源图/文字查看与补跑、样本数据包、字段说明、图文质量抽样与调用耗时/费用报告。这里的“记忆”仍是上游观察文字，不建设记忆提取/融合/检索引擎。

## 7. v0.8：跨日、多用户与恢复加固

**特性输出**：小规模跨日/多用户试验；更复杂的对象比较、缺项补看、子任务局部调整；中断恢复对照与行为/图文质量评审。

**验收**：用户优先顺序、虚拟时间、结果后反馈、描述独立推进持续成立。分别在意图保存后、动作发送后、效果核验前中断，检查重复副作用和数据缺口。保存部分结果后恢复不重复计数或重采成功活动。披露共享账号推荐环境的影响。

评审用户差异、跨日稳定、机械重复、偶然行为、对象量核对、错误完成主张、摘要是否足够，以及描述漏字/幻觉。样本与阈值在试验前约定，不能由代码测试通过代替效果结论。

**交付**：跨日数据样本、失败/恢复案例、质量与成本报告、必要的下层改进。短技能或经验复用仅在样本显示收益时追加，可作为 v0.8.x；不默认建设完整行为库或自动经验学习系统。

## 8. v0.9：长周期运行与数据管理

**特性输出**：按用户/活动/图像/调用的服务端分页与完整检索、增量刷新、描述积压、真实资源/调用预算、停止继续、原图与数据库一致备份及迁移。

**验收**：在已声明的样本规模上不漏页、不重复、不串用户；执行和描述进度分别可查；旧调用不因仅载入最近 1000 条而无法查找；预算耗尽保留进度和原因，不改写用户当天的行为选择。披露实测吞吐、图片存储和模型成本。

**交付**：可用的查询/进度功能、备份恢复工具、较长区间试运行报告、容量与成本建议。可配置一年不等于已采集一年；规模逐步提高，采集数据质量先于数量。

## 9. v1.0：明确范围的研究采集交付

v1.0 指首个约定环境与 APP 范围内可重复部署、运行、恢复和消费数据的版本，不代表通用手机 Agent、全 APP 覆盖或年度行为研究结论。

交付固定的框架/模型/设备/APP/配置版本，Windows 主程序和必要接入组件、启动诊断、数据格式与样例、测试/真实运行/GUI 验收证据、已知问题和更新/回退说明。第二台电脑实测应覆盖 GUI 启动、配置检查、创建任务、推进/暂停恢复、图文查看、停止与迁移。

发布门槛：约定功能和异常清单通过；来源与数据边界正确；未验证/未接入处有显式状态；能复现实验输入和运行证据。模型服务、设备权限、APP 环境和预算作为运行条件列清楚。

| 测试与限制报告 | 自动化、真实模型/设备、GUI、另一电脑分别测了什么；没测什么；行为效果不能从完整性推出 |
| 数据兼容与发布文件 | 旧 Run 能否恢复、增量迁移/备份方法；新包输出新副本；不因源码修改声称旧 ZIP 已更新 |

前面的 32 项回归是现有基线，不是未来固定测试数；新增持久化、设备与模型边界要配相应故障验证。框架引入新运行时/依赖时，重新交付部署检查，不能把当前 Mock 包“零安装、离线可用”直接承诺给所有真实接入组件。

**缺少本版独立用例或可操作调试界面，不能记为该版本完成。** 具体内容到该版本开发时再落实；未验证的范围如实说明。要求记录见[随版测试交付约定](VERSION_TEST_PLAN.md)。
