# 系统页面与架构 v0.2 · 2026-10-18

本轮依据用户纠正，将原先面向工程验证的 Demo 改为系统实际使用页面。复用原 SQLite、适配器、恢复、图像资产与导出模块，新增业务工作区与必要架构逻辑。仍按单机、少量用户推进，不把此次界面完成解释为真实采集或长期行为效果已验证。

## 使用路径

1. 双击 `start-web.cmd`，或执行 `node src/web-server.mjs`，打开 `http://127.0.0.1:4317`。后端修改后须重启，端口被旧实例占用时不要再并行启动同端口。
2. 「虚拟用户 → 生成用户」填写外部要求和数量。用户生成批次、每次请求/响应、原始要求与固定人设独立保存。
3. 「仿真任务 → 新建仿真」选择用户快照、开始日期、跨度与 APP。预设 1/7/30/90/365 天，也支持自定义正整数天数；结束日期按含首日的天数计算。用户快照锁定，后续复用用户库不会改写已有任务。
4. 「行为规划」可以仅请求当前待执行日计划。调度器不决定活动内容，也不在任务创建时预编全年计划。
5. 「下一活动」推进一项并完成该项上层反馈；「推进一天」完成当前用户一个尚未结束的虚拟日；「开始/继续生成」持续推进区间。优先连续完成同一用户的区间。
6. 「暂停任务」保存暂停请求，在当前活动结果与反馈提交后停止继续派发。图像描述独立推进；下一次继续会清除暂停请求。立即停止与中断演练收在开发验证中，仍遵守执行器授权恢复边界。
7. 「行为序列」查看已保存实际结果、手机指令与截图；「生成记忆」查看逐图原文、失败、模型/提示版本、加工来源及真实时间；「调用链路」查看真实调用、Trace、父调用、请求/响应与错误。全部视图支持当前任务的用户/虚拟日筛选，序列与记忆还可按 APP 筛选。
8. 可补齐文字、导出 JSONL/元数据、运行独立完整性检查；检查不自动重规划。

## 实际运行与 Mock 的边界

| 能力 | 本轮状态 |
|---|---|
| 用户生成编排、批次、来源、用户 ID 与用户库 | 实际调用、实际持久化 |
| 人设补全内容 | Mock 模板；不承诺满足所有自然语言约束 |
| 任务创建、用户绑定与人设快照、区间计算 | 实际运行 |
| 事件调度、按活动/用户日限额推进、暂停与恢复 | 实际运行 |
| 各用户虚拟时钟与日进度 | 实际落盘，禁止回退；无按真实月份等待 |
| 每日计划与活动后调整 | 实际请求上层适配器；响应内容 Mock |
| 页面理解、具体手机指令与内容对象 | Mock，尚无 hipyum 集成或完整手机 Agent |
| 截图文件与动作关联、哈希与来源 | 实际保存；图像字节为明确标识的合成资产 |
| 逐图描述的队列、顺序、失败与补跑 | 实际运行；转文字内容 Mock，未调用 VLM |
| 调用链、请求响应、起止、父子关系与中断 | 实际调用时记录，不预造成功链路 |
| 行为自然性与长周期产能 | 尚未验证 |

APP 候选包含用户列出的今日头条、大众点评、携程、美团、铁路12306、小红书。为覆盖商城类别，工程上补充可选京东候选，默认不勾选；它不是用户已经选定的首个真实 APP。所有能力描述均为拟接入范围，不是已验证 API，真实接入仍要确定首个 APP 和允许能力。

“生成记忆”当前按截图转文字的上游观察文本实现，保留原先不实现记忆提取、融合、更新或检索引擎的范围。它不是稳定偏好、结构化长期记忆或已融合的用户画像。同一对象的动作前后图像可产生两条独立观察，不擅自去重或加工。

## 新增模块与持久化

| 模块 | 文件 / 记录 | 责任 |
|---|---|---|
| 用户库 | `src/user-library.mjs`；`.data/.users.sqlite` | 生成批次 profiles / generation_calls；原始要求与 Mock 来源 |
| APP 能力目录 | `src/app-catalog.mjs` | 当前指定候选能力与 Mock 接入状态 |
| 调度器 | `src/scheduler.mjs`；`runner.mjs` 保留统一入口 | 只请求上层、派发下层、保存反馈、推进区间 |
| 用户日进度 | `schedule_days` | planning / planned / running / complete |
| 虚拟时钟 | `virtual_clocks` | 当前日期、活动时间锚点、阶段、真实更新时刻 |
| 暂停控制 | `run_controls` | 持久化 pause_requested，活动反馈边界生效 |
| 调用记录 | `src/tracing.mjs`；`call_spans` | trace_id / parent_id / module / mode / input / output / error / owner_pid / 真实起止 |
| 系统页面 | `web/index.html`、`workspace.mjs`、`workspace.css` | 业务页面；进度来自服务，不用浏览器内假进度 |

`initialize` 对来自用户库的用户保存固定 `persona_snapshot`，不再次生成人设；快照调用输入关联 `source_user_id` 和用户生成调用 ID。规划上下文包括固定人设、当前虚拟日、APP 能力、外部生成要求、有限近期实际及当天计划。

`prepareNextDay` 只为顺序中的第一个未结束用户日请求计划；重复请求复用已保存计划，不提前执行。`runSimulation` 新增 `maxActivities`、`maxUserDays`，限额停止时先保存活动反馈；每日活动内容仍只由规划适配器产生。

虚拟时间按任务中的本地活动锚点单调推进。日终 23:59 是运行管理边界，不是额外行为事件。事件顺序仍由用户、虚拟活动时间、活动序号、步骤和截图序号确定，不伪造虚拟秒数。真实采集时间、模型处理时间与管理更新时间各自保存。

schema v1 自动增量迁移到 v2。旧数据没有时钟检查点时，管理进度只从已保存的计划、实际结果与反馈重建，记录管理审计；不新增截图、动作、描述或执行事实。进程中断的未完成调用由新执行 worker 根据退出的 PID 标 interrupted，不改写其为成功。

导出 `run.json` 额外包含虚拟时钟、日进度和调用记录；原事件原文与加工字段仍独立。资产默认按路径引用，不包含在 JSON 文件里。

## 新增接口

- `GET /api/system`：APP 目录与模块实际 / Mock 边界。
- `GET /api/users`、`POST /api/users/generate`：用户库、生成批次与实际生成请求记录。
- `POST /api/simulations`：按用户 ID、名称、开始日期/跨度和 APP ID 创建任务并固定人设快照。
- `POST /api/runs/:id/jobs`：新增 `plan_next`、`next_activity`、`next_day`；原运行、描述、导出检查 API 保留。
- `POST /api/runs/:id/pause`：请求活动反馈边界暂停。
- `GET /api/runs/:id/calls/:call_id`：单次实际调用的输入/输出和关联。

当前调用列表只载入最近 1000 条元数据，按需获取请求正文，支持 Trace 筛选；序列与记忆在页面分页。年度任务的配置与渐进推进已验证，完整年度数据的查询分页、长期吞吐和费用尚未做产能验证，不能据此宣称一年规模已可稳定真实生产。

## 验证与保留问题

25 项测试覆盖原有恢复/顺序/用户隔离，以及人设库持久化、用户快照、365 天跨度、惰性每日规划、按活动/用户日推进、虚拟时钟单调性、反馈边界暂停、schema 迁移和旧检查点重建。

浏览器实测生成 3 位用户，选择 2 位创建七日任务；验证年度选项可计算 730 用户日；只生成当日计划时没有执行事实；推进到两个用户日后保存 6 项活动、28 张合成图像、28 条观察文字及实际调用记录。其余用户日仍待推进，不把该样本标为完整年度或完整七日生成。

下一轮最小真实接入仍缺 hipyum 文档与设备、首个 APP 与账号条件、文本/VLM 服务、下层页面理解与逐步决策方案。结果摘要能否支撑上层调整、固定人设能否产生自然长期行为、共享账号的环境影响仍需小样本实测后逐项讨论。
