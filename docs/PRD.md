## 为什么建设 BehaviorLab

长期记忆研究需要能追溯来源的用户行为序列：同一个用户在不同时间做了什么、手机实际出现什么、操作产生什么结果、哪些内容仍未知。仅生成一段“用户浏览了商品”的文本，无法回答实际看到的页面、动作是否生效、活动完成多少，也不便对失败进行分析。

项目的长期目标是生成带用户、时间、活动、图像、原始响应与结果依据的数据。当前 v0.4 先解决下层手机操作的接入和评估：让研究与开发人员在相近起点下选择任务、框架与模型，真实执行单项活动，并保留成功、部分完成和失败的全过程。

## 使用者与主要场景

| 使用者 | 需要完成的工作 | 应取得的产出 |
|---|---|---|
| 研究与评测人员 | 定义任务、组织组合评估、核对结果 | 可比较的输入、环境、执行证据、耗时和调用量 |
| 框架接入开发者 | 接入或替换操作框架、定位协议与工具问题 | 离线契约、原生循环记录、真实效果单独说明 |
| 工作台开发者 | 改进配置、运行观察、轨迹回放与审核 | 与后端相同的状态和证据，明确的操作入口 |
| 数据使用者 | 查看或导出行为、截图、调用与判定 | 保留原始来源和未知项的数据，而非补写的成功摘要 |

典型流程：创建命名任务 → 在任务内选择起点 → 选择框架与模型 → 明确开始测试 → 观察过程 → 查看证据并审核 → 导出结果。组合评估枚举框架、模型、任务的组合，每项都保留自己的输入与结果。

## v0.4 要实现的业务能力

| 编号 | 需求 | 当前实现与边界 |
|---|---|---|
| Q01 | 定义可复用任务 | 保存名字、应用、目标、判定要求、禁止操作和修订；内置任务可复制，自定义任务可编辑或停用 |
| Q02 | 起点配置属于任务 | 选择已有起点，或把当前状态命名；内置桌面和洛书伴随态在显式执行时复原，不要求像素完全一致 |
| Q03 | 框架与模型可替换 | 保留 Midscene、MobiAgent、Open-AutoGLM；提供样本依据的默认推荐，用户选择优先 |
| Q04 | 支持单项与组合测试 | 单项三个维度各选一项并命名；组合各维度可多选，运行记录分别保存 |
| Q05 | 过程可观察 | 当前用例、逐步截图、原始模型回复、解析与动作、设备信息、耗时和用量可查看；投屏和 HiLog 独立管理 |
| Q06 | 不混淆执行与业务成功 | 框架返回结束、模型自报完成、动作返回、人工通过是不同事实；未知动作效果保留核对状态 |
| Q07 | 有限范围的定位恢复 | 显式坐标异常尚未交给设备时，重新截图并新增最多两次定位请求；用量仍计入总限额，不重放已执行动作 |
| Q08 | 失败可以分析 | 保留拒绝、停止、异常、未确认用量和原始回复；结果页支持筛选和逐条回放 |
| Q09 | 查看历史不重跑 | 随包历史只读；导出结果与原图，不自动恢复旧队列或追加真实调用 |
| Q10 | 保留主仿真工程基座 | 用户库、用户／日／活动调度、虚拟时间、持久化和执行／描述分离实际运行；内容与手机执行仍为 Mock |

“淘宝-浏览50个商品”是一个任务定义，不表示已完成50件去重验收；任务中的自然语言目标也不会自动获得数量台账、身份识别或条件核验能力。

## 必须保持的事实与约束

- 输入、任务修订、起点、手机型号与系统、框架与模型、源码来源和限额须能追溯。
- 请求数、框架动作数、物理输入数和截图数分别计量。一次请求可能只有判断，也可能让框架执行多项动作。
- 新测试默认不设请求、步数、动作、时长和模型等待上限；操作者应按任务设置预算。网络失败不自动重试，坐标纠正属于另外记录的新请求。
- 密钥只在受控调用边界使用；提交、评审材料和普通运行导出不得包含可用密钥。原图和 HiLog 可能含业务内容，分享前检查具体记录。
- 不因测试驱动产生任务未要求的购买、支付、发布、关注、删除或新增系统权限。用户显式启动与项目约束仍是执行前提。
- 未知费用不填零；短文本连通不证明图片理解、动作协议或 GUI 任务完成。
- 主仿真与独立手机工作台分开统计。Mock、注入夹具、原生离线循环和真实手机证据分别标识。

## 已有证据怎样解释

四个历史任务是计算器、存储、淘宝和小红书，三框架 × 三模型 × 四任务共36单元；助手判定16通过、10部分完成、10未通过，用户复核待定。历史请求331次、关联原图1,486张。后续代码保护的离线通过不能反向升级这些历史成绩。

preview.14 Windows包已有207/207离线回归记录。31项能力清单是证据与缺口的核对表，不是31项全部真实通过。当前整理另记录审查与验证范围，见[代码审查](CODE_REVIEW_V04_20261030.md)。

## 当前不承诺的范围

不承诺任意应用、任意手机、多小时无人干预稳定性、自动完成业务计数或跨框架会话恢复。真实人设、真实日计划与存档逐图描述尚未接入 v0.4 主流程；长期记忆提取、融合、检索和评估算法未作为本版功能交付。源码复用与新增能力应通过单独的需求、设计和验证推进。

后续分工见[模块划分讨论稿](COLLABORATION_MODULES.md)，当前实际实现见[架构说明](ARCHITECTURE.md)。

## 非功能需求

| 编号 | 要求 | 可核对方式／当前边界 |
|---|---|---|
| N01 | 可复现 | 任务和起点有修订、来源与环境记录；不保证动态 APP 页面像素一致 |
| N02 | 可追溯 | 请求、回复、动作和图像可关联；损坏证据必须可见是修复目标，当前有审查 R02 缺口 |
| N03 | 安全停止 | 停止后不再派发新输入，保留在途不确定性；父进程崩溃保护有审查 R01 缺口 |
| N04 | 可维护 | 固定框架注册入口、模块职责与离线验证；现有密集语句和跨层依赖继续列为技术债 |
| N05 | 可部署 | Windows x64 完整包、依赖检查、停止和回退；第二台电脑与长时稳定性不以本机检查代替 |
| N06 | 数据隔离 | 本地密钥、数据库、缓存、依赖和新运行不提交；历史附件与本机数据来源分开 |
| N07 | 长任务可观察 | 有步骤与用量，不虚构百分比；当前全量轨迹读取有扩展性限制，未规定或证明吞吐 SLA |

## 验收与异常矩阵

| 编号／覆盖需求 | 场景 | 应核对的结果 | 证据入口 |
|---|---|---|---|
| A01 / Q01–Q04 | 新任务、修订冲突、单项／组合与起点绑定 | 选择有效，冲突不覆盖；运行冻结实际输入 | `tests/phone-workbench.test.mjs`、`phone-bundled-tasks.test.mjs` |
| A02 / Q05、Q08 | 查看一条历史轨迹 | 原图、回复、动作、型号、时间与审核可关联 | `tests/phone-trace.test.mjs`、`phone-process.test.mjs`、`phone-image-time.test.mjs` |
| A03 / Q06、N03 | 非法动作、未知效果、取消与异常退出 | 非法动作不送出；未知效果不被写为通过、不自动重放 | `tests/phone-action-effects.test.mjs`、`phone-protocol.test.mjs`；R01 另有缺口 |
| A04 / Q07 | 坐标越界后重新定位 | 新请求有记录、最多两次纠正，只执行有效新动作；错误费用不填零 | `tests/phone-grounding-recovery.test.mjs`，均为离线验证 |
| A05 / Q09、N06 | 历史只读、密钥配置、导出和升级 | 不重跑档案，不返回明文密钥，不覆盖自定义任务修改 | `tests/bundled-history.test.mjs`、`model-settings.test.mjs`、`release-privacy.test.mjs` |
| A06 / Q10 | Mock 主流程中断、描述失败补跑 | 缺反馈只补反馈、描述只补已有图，原成功活动不重采 | `tests/pipeline.test.mjs`、离线教程 |
| A07 / Q05 | 视频、手动／自动 HiLog | 生命周期独立，收尾及文件可检查；不将出帧算作业务成功 | `tests/phone-video.test.mjs`、`phone-hilog.test.mjs` |
| A08 / N02、N07 | 损坏日志、长轨迹和事件追加 | 应显式报告损坏、增量查询不丢不重；当前 R02/R03 未补齐 | [审查与复现](CODE_REVIEW_V04_20261030.md) |
