## 1. R01：输入由已登记的 worker 持有

以前输入锁只检查父PID；父进程死亡后即使旧worker仍活着，也可能重新授予输入。现改用已有的带host、token与worker身份的公共设备租约，不另建一套锁算法。

1. 父进程取得租约，fork后登记worker PID。
2. worker发IPC许可请求；父进程确认登记后的租约，再发送匹配许可。worker校验锁文件、token、owner、父PID及自身PID后才初始化任务。
3. 每次HDC命令前重查所有权、父IPC连接和取消状态。失败标记命令尚未送出，不把这种失败写成动作效果未知。
4. 父进程在child `close` 后收尾，释放时仍需确认worker不存活；失败保留锁和诊断。异常退出状态由事件推导，不能默认为成功。

新逻辑复用同一共享锁路径。已知死亡的新格式锁可回收；旧格式、其他host、损坏或身份不确定的锁保守返回409，不自动删除。进程身份检查不是任意OS崩溃安全续接：跨安装目录互斥、PID复用时的精确身份、在途HDC工具硬杀后的设备效果仍未做系统验证。

关键实现为 `src/phone-worker-lease.mjs`、`src/phone-lab.mjs`、`src/phone-device.mjs` 与 `scripts/phone-lab-worker.mjs`；公共租约算法本身保持。

## 2. R02：完整性成为显式状态

统一读取器保留可解析事件，并产生独立诊断；不修改坏文件、不把坏行原文复制到JSON或网页。

| 字段 | 语义／兼容 |
|---|---|
| `ledger_integrity.scope` | 固定为 `ledger_parsing`，只描述账本解析 |
| `status` | `complete`、`pending_tail`、`incomplete`、`missing`、`unreadable` |
| `complete` | 仅全部非空行可解析为带type对象且不存在待写尾行时为true；不证明业务通过 |
| `valid_events`、`invalid_lines` | 已解析事件数、稳定坏行数；空文件为0/0，不凭空补事件 |
| `issues` | 1起始行号与错误码，最多100条；超过时置 `issues_truncated`；不泄露坏行内容 |
| `pending_tail_line` | 活跃记录最后一个未换行的非法JSON片段行号，其他情况为null |

仅“活跃＋文件末尾未换行＋尚未组成JSON”暂记为 `pending_tail`；内部坏行、已换行坏行或结束后截断均为稳定异常。缺文件和不可读分别报告。字段随snapshot、过程游标响应和JSON导出返回，即使游标没有新事件也返回最新完整性。

结果和过程共用告警展示：等待尾行用状态提示，稳定异常明确标出损坏位置。坏账本不允许追加任何审核，避免污染原文件；写入器拒绝继续损坏账本，写入失败后停止后续追加。有效但无末尾换行的账本可以补分隔符并继续有效seq。

所选截图在通过审核前核对存在性与SHA-256；图片读取同样检查，页面显示失败提示。未引用图像没有被全量扫描，`complete:true`不能当作“所有图片和事件语义均已校验”。合法旧记录保持可读；旧的用户判定保留，告警不冒充新的业务结论。

## 3. 诊断与协议

- 记录JSON仅有已解析事件、完整性诊断和运行元数据；损坏的原始行须在原文件／诊断ZIP核对。
- 结束且可写的本地记录可导出诊断ZIP，原始坏账本按原字节保留，新增 `ledger-integrity.json`。原有 `capture-*` 文件排除规则保留；只读随包档案不追加审核或重新打包。
- 自动日志收尾若因坏账本不能追加诊断事件，将错误记入HiLog元数据，保留原账本。
- 新运行冻结协议为 `phone-lab-v14-worker-lease-ledger-integrity-v1`，并纳入新增源码哈希。旧input/result/图片不改写，软件版本和已发布标签不冒名升级。
