## 验证

本机实测 Node v24.19.0 / SQLite 3.53.3。`node --test` 的 13 项验证全部通过，包括：

- 2 用户 × 2 虚拟日闭环；8 个活动结果、8 个调整决定、24 张合成图像。
- 计划目标 3、实际完成 2；局部计划版本保留旧记录；已结束事实不被改写。
- 子进程在动作意图/图像已写入后直接退出，恢复后不重复生成步骤和截图。
- 子进程在结果已写入、反馈未写入时退出，只补反馈，不重采。
- 描述子进程中断后只补缺项，保留 interrupted 尝试历史。
- 描述失败阻塞活动内后续图像，其他活动继续；显式重试不改写成功原文。
- 下一活动可在上一活动描述完成前执行；描述仅在当前活动结果落盘后启动，活动内严格有序。
- 用户上下文有界且隔离，跨用户来源外键拒绝写入，步骤不能越出指定 APP。
- 不确定动作恢复被拒绝时停止，不盲目重放。
- 上层空计划时管理器不另造活动；blocked 结果仍产生反馈。
- 重试上限、资产损坏、离线报告不重规划、重复 worker 和来源标记约束。

初次沙箱测试受系统临时目录 rename 权限限制；授权运行同一测试命令后 13/13 通过，非跳过断言或放松恢复约束。常规项目目录演示可直接运行。

## 如何复现

按 README 的六条 CLI 命令创建自己的 `.data/demo`。已运行示例另存在 `.data/phase-a-demo`，可直接执行 `status`、`export`、`check` 查看；无需重新 init。`node --test` 用独立临时目录，子进程故障注入后自行清理。

示例配置刻意制造两张首次描述失败，执行完成时不会把剩余描述冒充完整。`describe --retry-failed` 完成后导出 24 条有序合成观察事件，检查报告仅表明工程完整性；行为效果仍为未评估。

## 真实接入前最少四组输入

| 输入 | 最少内容 |
|---|---|
| hipyum | 接口文档或最小调用示例、连接方式、设备/系统、观察/截图/动作返回结构、异常与超时语义；尤其截图相对动作的先后、动作是否可能已发生 |
| 首个 APP 与环境 | 明确 app_id/APP 名、允许的浏览能力与动作范围、测试设备与登录账号状态；首轮只跑一个用户一天少量活动 |
| 模型服务 | 文本/VLM 的协议、端点和模型名、图片输入形式、配置方式；密钥用环境变量，不放进文档/配置/数据库 |
| 下层决策方案 | 已有页面理解/逐步决策代码或技术材料；如仅有手机操作 API，需要共同确定最小观察与决策循环、停止和恢复策略 |

拿到资料后，先用真实服务走通一个用户一天的极小样本，再对齐“结果摘要是否足够支撑上层调整”这一假设。暂不扩大到年级或分布式系统。

## 限制

Mock 人设、规划和描述都是确定性夹具，不是模型自主行为，更不是真实采集数据。没有 hipyum 集成、页面理解 Agent、真实设备调度、真实 APP 账号隔离、模型计费/限流、行为自然性评估或硬件断电原子性承诺。共享账号环境影响仍未解决。文字改编只留来源接口，无默认策略。真实恢复的终止/重试权限和未知副作用处理仍须接入前讨论。
