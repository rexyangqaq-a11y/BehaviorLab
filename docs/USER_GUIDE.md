# v0.4 使用指南

适用已发布 `v0.4.0-preview.14`；内部日常测试按当前明确授权进行。先读[产品范围](PRD.md)和[部署说明](DEPLOYMENT.md)。真实测试、历史回放与 Mock 示例分别使用，不能互相代替验收。

## 1. 查看历史结果

进入 `/phone-lab#results` 的“结果与对比”，按记录来源、框架、模型、任务、手机和判定筛选。随包历史36项是只读档案，点击详情查看原图、模型回复、动作、时间和结果依据；也可离线打开 `test-archive/index.html`。

历史四任务 × 三框架 × 三模型，16通过、10部分完成、10未通过，用户复核待定。查看不会创建运行或恢复旧队列；框架 `ended` 不是业务通过。新协议和保护没有以这些旧记录重测。

## 2. 维护任务与起点

在“任务列表”查看现有任务，或创建命名任务，填写应用、包名、任务目标、判定要求与禁止操作。起点只在任务设置中选择：已有起点、命名的当前状态、内置桌面或洛书伴随态。测试页面不另配置起点。

内置起点在显式开始后自动复原并核对；相近条件不要求像素一致。任务需要进入 APP 的步骤由框架完成。洛书通用机型资料按机型、系统、屏幕和方向匹配，不匹配时停止核对，不猜位置。

首次交互启动会加入可编辑“淘宝-浏览50个商品”任务修订3，已有同 ID 的编辑或停用不覆盖。这个定义不表示系统已经证明50件计数或去重完成。

## 3. 选择模型与测试组合

在系统设置配置自己的视觉模型 API、模型名和密钥，点击“保存此服务配置”，确认必填项完整后回工作台。仅填写的草稿不会生效；文本响应也不证明图片和动作协议已通过。

单项测试：填写名字，框架／服务／任务各选一个。组合评估：三个维度各可多选，核对组合数再开始。三框架保留，默认推荐 Midscene + qwen3.7-plus 只依据四题3通过1部分完成样本，用户配置优先。

**新测试默认不限请求、步数、动作、时长和模型等待。** 需要控制消耗时显式填写限额，按任务复杂度确定。请求数、动作数、物理输入数和截图数分别计量；一请求不保证一动作。

## 4. 显式运行与观察

确认可用预算与允许操作，再连接唯一授权手机、允许调试并保持解锁。点击开始后查看“测试过程详情”：当前用例、轨迹、图片、原始回复、动作和用量。

可选连续投屏；页面的连接检测与自动投屏会访问设备，不是纯历史查看。当前手动 HiLog 与每测试自动 HiLog 两路独立，自动日志从起点准备前开始至测试收尾；关闭网页不会停止后台抓取，服务正常退出会关闭会话。

可识别坐标异常在送出前被拒绝后，最多新增两次定位请求，仍受原限额和取消控制。网络失败、未知用量、未知动作效果等不因此自动重试；任务语义错误不能保证被坐标检查发现。

## 5. 停止、核对与导出

点击停止，等待在途动作与日志收尾。未知效果进入核对状态，不直接重放。已知输入锁崩溃窗口见审查 R01，不能假设异常退出后任意重启都安全。

在结果详情查看终图和全过程，填写用户判定及依据；助手初判与用户审核分开，用户结论优先。日志损坏或关键证据缺失时不把“界面能显示”当作证据完整。当前损坏行提示缺口见 R02。

测试和日志结束后可下载完整 JSON、含原图的证据 ZIP，或相应 HiLog。导出含业务截图／文本，分享前核对具体内容，不分享整个带密钥和数据库的目录。

## 6. 无手机示例与排错

完整无手机／无模型示例见[开发指南的 Mock 教程](DEVELOPMENT.md#无手机完整示例)。它验证恢复、描述与导出机制，不产生真实行为样本。

故障先看启动器地址、`.runtime/server.log`、离线诊断与该运行原始记录。检查缺失依赖、配置是否保存、设备是否授权、截图／动作协议、停止与限额，分别判断问题层次，不把所有失败都归为模型能力。代码审查与未验证范围见[审查报告](CODE_REVIEW_V04_20261030.md)。
