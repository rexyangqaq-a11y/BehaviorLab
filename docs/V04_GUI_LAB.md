# v0.4-preview.1：下层 Agent 单活动验证台

日期：2026-10-20，本文记录该预览阶段。**这是可操作的阶段预览，不是正式 v0.4 完成声明。** 交接更新（2026-10-21）：三个模型已保存且独立短文本连通通过，主流程仍未接入真实模型/真机；当前回归 46 项，本文验收时的 44 项为历史数量。完整最新状态见 [CURRENT_STATUS.md](CURRENT_STATUS.md)，框架最终选择仍由用户决策。

## 1. 本次可以实际使用什么

通过现有 `01_START.cmd` 启动系统，进入「系统设置 → v0.4 下层 Agent 验证」。默认直达地址：[验证台](http://127.0.0.1:4317/#/settings/gui-lab)。启动器若选择其他端口，以启动结果为准。

界面按试验流程递进：

1. **检查试验条件**：检测 Node 环境、已安装候选 SDK 的离线契约、HDC 可发现性和设备列表、已保存的手机决策模型预设。不会请求模型；如果发现 HDC，仅调用 `list targets`，不操作页面。
2. **准备单活动用例**：选择候选与本版工程用例，编辑目标 APP、活动目标、起始条件、完成依据，设置步数和本次执行时限。候选选择只保存实验信息；当前夹具的动作和判定逻辑由用例固定，不解释编辑的活动文字。
3. **执行记录与证据**：运行明确标注的 Mock，查看目标与实际数量、步骤、父子调用、动作意图/发送/返回、合成图像和结束原因。可以停止、显式续跑安全的 Mock，并导出 JSON。运行期间固定查看当前记录；结束后可选择最近 50 条历史记录。

现有用户库、每日调度、虚拟时钟、任务数据和描述队列继续复用，验证台不向其中注入夹具数据。单活动验证不推进虚拟日期；真实起止时间单独留存。存档图转文状态为 `not_run`，没有把合成图像或夹具核对结果称为研究采集数据。

## 2. 框架代码验证实际推进到哪一步

隔离目录 `integrations/midscene` 安装了 **`@midscene/harmony=1.16.0`**，依赖树固定在 `pnpm-lock.yaml`；安装时禁用了依赖安装脚本。主系统没有新增必需的第三方依赖，缺少该目录时仍可运行，环境检测显示候选未安装。

选择 Midscene 作为本轮可替换验证样例的依据，是它的[官方鸿蒙路径](https://midscenejs.com/platforms/harmonyos)与现有 Node 工程便于衔接；不代表已经选定生产框架。[框架完整比较](V04_GUI_FRAMEWORK_SELECTION.md)继续保留 MobiAgent、Open-AutoGLM 及其他候选。

本轮对实际安装包验证了：

- 可导入 `HarmonyAgent`、`HarmonyDevice`，可读取设备动作空间及 `aiAct`、`aiAssert`、`destroy` 方法。
- 通过真实 SDK 的 `Tap.call` 入口，验证记录顺序为「动作意图 → 工具替身 → 返回记录」。工具端替换为假的 HDC，不产生手机操作。
- 新增 `instrumentGuiDevice` 记录包装：原 SDK 保留规划和操作实现，包装动作调用与截图返回。动作意图记录失败时不进入操作；动作抛错或返回后记录失败均标记效果未知，不自动重发。
- 截图包装要求先保存返回图像，再把观察交给调用方；留图失败会中断该调用。此项的全部截图测试使用替身，尚无 SDK 真机截图证据。

限制：包装粒度是 SDK 的一个动作；例如输入动作内部可能含多个 HDC 命令，**当前没有证明每个底层命令都被独立记录**。SDK 包含 `RunHdcShell` 等额外动作，真实模型执行前必须明确开放的动作范围，不能把它们全部默认交给模型。本轮没有运行 `aiAct` 决策循环，没有请求模型，也没有获得手机完成率。

需要重新安装/独立验证时，在已有 pnpm 11 的开发环境使用：

```powershell
pnpm --dir integrations/midscene install --frozen-lockfile --ignore-scripts
node integrations/midscene/probe.mjs
```

HDC 在开发环境准备好后，可通过 PATH 或 `HDC_HOME` 指向其目录，再点击检测。具体手机型号、鸿蒙构建、APP 和权限均需真实核对，不因检测到一个设备 ID 就宣称兼容鸿蒙 6/7。

## 3. 本版独立用例

2026-10-21 补充：[第二类 GUI 任务效果与性能用例](V04_GUI_EVALUATION_CASES.md)已有 14 条待审核初稿及 JSON；与下面 7 类工程 Mock 分开。新清单尚未接入此网页，不能从现有 Mock 按钮执行，也没有真实成绩。

补充：另一对话「框架对比」的全部比较维度已纳入[完整框架验收用例](V04_FRAMEWORK_TEST_CASES.md)：15 个维度、31 项，包含执行循环、各层记忆/续接、经验缓存、餐厅条件/评价/收藏、淘宝/京东百对象、PC/服务器部署和有效对象成本。页面的「框架对比验收清单」支持按维度和候选筛选、展开与 JSON 下载；这些是尚未执行的真实框架验收定义，不会由下面的 Mock 按钮运行，也不触发真实模型请求。网页、导出和文档共用一份用例定义。

以下是本项目自建的工程夹具，不是 AndroidWorld 等公开基准的迁移结果，也不产生框架分数。APP 名称为拟测试场景示例，不表示已确认鸿蒙版本兼容。

| 用例 | 工程触发条件 | 应看到的结果 |
|---|---|---|
| 系统 APP · 只读查看 | 确定性成功对象 | Mock 完成，1 个证据对象，动作前后图各 1 张 |
| 新闻 · 两个不同对象 | 两个不同标识 | Mock 完成，实际 2/2，2 步、4 张合成图 |
| 美食 · 重复对象不累计 | 两次返回同一对象 | partial，实际 1/2，不按点击次数计量 |
| 社区 · 无结果 | 夹具返回空列表 | blocked，实际 0，保留空结果证据 |
| 模型异常 · 不发送动作 | 决策阶段抛错 | failed，工具发送次数 0，不悄悄补动作 |
| 工具超时 · 效果未知 | 动作已发送，未得到返回 | needs_attention，只发送一次，不开放自动恢复 |
| 循环与停止 · 有界退出 | 连续返回同对象 | 连续 3 次无进展后 partial；也可主动停止或受步数/时限约束退出 |

步数限额覆盖同一记录的已创建步骤；时间限额针对每次执行/显式续跑，不能据此推断真实手机命令可被立即取消。Mock 停止/恢复具有无外部副作用条件，真实恢复策略尚未实现。

## 5. 数据与发布边界

- `.data/.gui-lab.sqlite` 保存实验输入快照、结果、步骤、事件与检测记录；`.data/.gui-lab-assets/` 保存图像及哈希。
- 导出的验证 JSON 包含输入、结果、事件和资产索引，不是研究 JSONL，不内嵌图像字节。图像仍可从对应实验逐张查看；尚无一键完整资产包导出。
- 模型预设只留 ID 和配置版本，标记 `applied=false`，不读取或复制密钥；填好模型设置不会启用真实执行。
- 当前便携包构建不复制实验数据库/图像，也不复制候选 SDK 依赖。没有生成新的 Windows 发布 ZIP，历史包不随源码自动更新。

## 6. 距正式 v0.4 还剩什么

需要用户收敛实际试验候选；准备 HDC、手机构建与测试 APP，随后在页面填写选定的模型服务。继续实现实际框架 runner、模型/工具调用记录、开放动作范围、停止语义和业务完成核对，再用同一批鸿蒙活动补真实证据、失败类型、耗时和费用。正式版本仍要求至少一个候选在真实模型/设备条件下跑通基础活动。

对真实 SDK 与 hipyum 的选择、动作粒度、完成判断和模型分工逐项评审。本预览不替代这些决定，也不把 Mock 用例通过当作开源框架选型结论。
