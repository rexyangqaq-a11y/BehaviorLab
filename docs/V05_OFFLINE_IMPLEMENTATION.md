# v0.5 首轮离线接入记录

日期：2026-10-25。源码`0.5.0-preview.1`，分支`codex/v05-single-activity`，从`codex/v04-handoff-20261025`开始。用户核对概要设计及实施范围后答复“继续”，本轮进入已授权的离线实现与验证。本文是实现事实，需求见[修订3](V05_REQUIREMENTS_CLARIFICATION.md)，总体方案见[概要设计](V05_HIGH_LEVEL_DESIGN.md)。**v0.5整体仍在开发，不作为真实下层接入完成或真机验收。**

## 已实现的范围

- Web、CLI、Web worker共用`createRuntimeAdapters`。旧`mock`兼容；显式`offline`接收手工／Mock活动。其他来源拒绝，不静默退回Mock。框架选择经三条注册分支进入公共派发边界，注入的仍是记录驱动夹具，`native_loop_executed:false`。
- 任务输入决定APP、目标、条件、数量及完成单位。对象型和条件型完成规则共用主调度；生产代码不保存商品点击序列。首个商品夹具从合成手机桌面开始，经启动、搜索和详情观察，目标2件实际核实1件，保存partial、重复、条件不满足及信息不全依据。故障夹具从动作边界开始，不冒称完整桌面流程。
- 开始前冻结活动、计划、APP、框架、运行限制、合成模型／工具来源及执行源码哈希；进程加载源码与磁盘不一致时要求重启，恢复不静默更换来源。
- 动作前保存意图与派发状态；步骤结果和进度同事务提交。恢复先校验已有图及未决步骤，消耗有限观察预算，已派发动作不重放；恢复轮次与起始时间跨重启保留。
- 对象／条件证据、已知实际量、恢复事件和人工历史持久化。人工三态复核带版本检查，保存意见零动作；继续／结束是独立命令。未知结束保留needs_attention与已知量；效果解决后仍须商品证据才能计数。结束时只补本活动反馈，不执行下一活动。
- 单活动调试页显示来源、实际／目标、证据、合成图、原始回复、恢复及执行／反馈／描述／导出阶段。工程入口提供四种夹具，选择刷新保留；复核草稿在轮询时保留。
- 共用文件租约检查父进程和worker存活、token归属；phone-lab派发接入相同框架注册边界和租约组件。旧格式或损坏锁、无法证明退出的控制者保守阻塞。

## 数据与接口

SQLite schema由2增量迁移至3，新增`execution_snapshots`、`activity_work_state`、`execution_events`。对象／条件／人工投影保存在工作JSON和最终结果中，使用事务、活动归属和revision比较保护；本轮没有拆成设计中的独立对象／人工意见关系表。schema 1与schema 2临时库迁移、旧Mock恢复均有工程测试；**没有打开或迁移现有私人运行库**。

新增接口为`GET /api/v05/template?scenario=...`、`POST /api/runs/:run/activities/:activity/review`与`.../resolution`，详情快照增加`executions`。执行复用jobs的`next_activity`及`expected_activity_id`。API只允许显式离线来源，拒绝活动／版本失配；CLI离线run和Web执行每次最多一个活动。查看、导出不创建真实执行资源。

## 复现方法

面向使用者的逐步操作和四种案例见[使用说明与例子教程](V05_USER_GUIDE.md)。

Node.js 24，无需新依赖。使用全新临时目录，保留历史运行：

```powershell
node src/cli.mjs init --config examples/offline-single-activity.json --data .build/v05-demo
node src/cli.mjs run --data .build/v05-demo
node src/cli.mjs export --data .build/v05-demo
node src/cli.mjs check --data .build/v05-demo
node src/web-server.mjs --port 4391 --data .build/v05-ui-demo
```

在隔离网页的“仿真任务→v0.5离线工程用例”选择框架／场景，创建后进入“单活动调试”，先生成计划，再执行一项。人工关注案例先复核保存，再显式继续或结束。原4317服务没有重启；它不会自动加载新源码。新源码没有打包，现有Windows ZIP仍为preview.9。

## 剩余实现与限制

真实主系统执行来源仍拒绝。注册派发和租约组件已共用，模型运输、会话、控制保护的大部分仍位于phone-lab worker；完整公共会话桥接、三框架安全续接能力、正式APP身份提取与真实端到端验收未完成。离线与真实设备使用分离的锁命名空间，避免合成测试占用现有设备；当前证明的是共用仲裁算法，没有证明主系统真实来源与phone-lab在同一物理设备上的排他。

PID存活检查对PID复用保守阻塞，尚无OS进程启动时间证明；租约变更guard崩溃残留时不会自动清理或抢占。描述仍Mock，阈值为工程默认值，不构成真实模型预算。真实副作用恢复、三框架全会话恢复、长期视频稳定性均未验证。

唯一下一步是在现有离线授权内补齐主执行器与原生框架的会话桥接／续接契约，以固定回复和注入设备验证；真实手机、供应商模型、视频和旧队列继续暂停，恢复真实执行另按用户明确指令办理。版本顺序保持v0.5下层部分接入→v0.6真实上层→v0.7存档VLM。
