## 2. 用户提供的 Xiaomi-GUI 页面是什么

入口：[RealMobile Trajectory Viewer](https://seerray-lab.github.io/Xiaomi-GUI/realmobile/viewer/)。它是 Xiaomi-GUI 项目下 RealMobile 基准的历史轨迹查看器，面向“同一任务，不同模型怎样执行”的检查，不是启动手机在线测试的控制台，也不是必须选用 Xiaomi 模型才能使用的工具。

本轮实际读取的 [catalog.json](https://seerray-lab.github.io/Xiaomi-GUI/realmobile/viewer/data/catalog.json) 含 **100 个任务、16 个模型、14 个 APP 标签**。官方 README 将任务分为基础操作、安全/反思、记忆/知识、复杂推理/规划，且包含跨 APP 任务。[官方任务与评分说明](https://github.com/SeerRay-Lab/Xiaomi-GUI/tree/main/realmobile)

当前目录的 APP 标签为：高德、哔哩哔哩、携程、得物、抖音、番茄小说、盒马、QQ、QQ 音乐、汽水音乐、腾讯视频、今日头条、微博、小红书。标签仅用作索引，不能推定逐项完整覆盖了指令提及的所有 APP。也不能据此宣称已有鸿蒙版任务、完整覆盖美团/大众点评/12306，或已经覆盖我们的百商品活动。

### 查看器与底层数据分别提供什么

| 部分 | 已核对到的内容 | 对我们的用途 |
|---|---|---|
| 任务目录 | ID、完整指令、APP 筛选、模型覆盖 | 给测试任务保留公开来源与检索入口 |
| 任务详情 | 评分细则、模型页签、多次执行记录选择 | 同一个任务逐候选比较，避免比较不同题目 |
| 逐步回放 | 每步截图、可得推理时长、模型原始输出；点击图可看大图 | 定位从哪一步开始偏离，而非只看最终一句完成 |
| 数据包 | `task.json`、逐步图片、Android UI XML、动作元数据 | 建立外部轨迹导入与离线评审样例 |
| 评分代码 | 每任务一份规则、子目标分值、匹配到的步骤证据 | 参考成功/部分完成的定义，而非按动作次数判定 |

依据：本轮抽查 `js/index.js`、`js/task.js`、任务 1/14 的详情 JSON；数据规范见[官方 Hugging Face 数据卡](https://huggingface.co/datasets/SeerRay-Lab/RealMobile)。网页显示的是已有轨迹；Android XML 等信息在底层包中，并非全部字段都在查看器上直接展示。

### 一条具体任务怎样评分

抽查任务 1：关闭 B 站后台播放。其规则将过程拆为到达相关设置、找到选项、完成关闭，累计约 0.33、0.66、1.0，并考虑应用内设置或系统权限的替代路径。不能仅凭模型发出 Complete 或点击过开关就认为已完成。[任务详情](https://seerray-lab.github.io/Xiaomi-GUI/realmobile/viewer/task.html?id=1)

任务 14 展示另一种结构：先在小红书按条件找到三家餐厅，再在高德比较距离，最后收藏符合条件的一家。它很适合参考跨 APP 条件保持、对象身份和分阶段完成证据的设计。修改城市、数量或取消收藏后，应成为注明差异的派生用例，而非继续冒充原版任务。[任务详情](https://seerray-lab.github.io/Xiaomi-GUI/realmobile/viewer/task.html?id=14)

原数据中的公开模型轨迹是尝试记录，可能成功、失败、绕路或误报；不能统称标准正确轨迹。某条公开轨迹看起来合理，也不代表它的模型自述就是事实。

## 3. 公开基准也需要抽查，不能当绝对真值

以下是本次可定位的核对结果，不是对全基准正确率的结论：

- `rules/1.py` 的 `evaluate_rule_3` 把“点击后台播放相关元素区域”与 `checked=false` 等条件列作候选，并在任一条件命中时返回成功。因此，代码路径存在以点击作为关闭依据的可能；本次未运行反例，不能声称已测出误判率。我们的迁移规则应要求操作后的关状态，必要时再核对效果。[源规则](https://github.com/SeerRay-Lab/Xiaomi-GUI/blob/main/realmobile/rules/1.py)
- `catalog.json` 的任务数组为 100，但其中 `summary.total_tasks` 为 108；任务 1 汇总写着 5 条路径，详情实际列出 16 个模型。说明汇总与轨迹索引可能对应不同统计批次，不能把现成 summary 当作当前全部模型的可比成绩。导入时要追溯每条结果的模型、执行批次和分母。
- 任务 3 的查看器目录摘要与抽查的 Python 规则，显示的阶段分值不同。导入需要锁定任务文本、规则、轨迹和版本，先核对一致性，不能混用不同快照。
- 评分引擎依赖 Android XML 中的 `text`、`bounds`、`checked`、包名，以及可选 OCR 属性。页面上出现某段文字、点击过某位置，与业务状态最终达成不是同一个证据强度。

这正是选用公开任务的价值：规则可审查、轨迹可复核、差异可记录；“公开”本身不保证每个条件都适合我们的设备或业务。

## 4. 对鸿蒙 NEXT，哪些可复用、哪些要迁移

| 资产 | 建议处理 |
|---|---|
| 任务意图、条件、子目标 | 尽量复用原版；保留源任务 ID、链接、原文及版本 |
| 原版轨迹与截图 | 作为公开参考和失败分析；不伪装成本系统真实运行结果 |
| 评分规范 | 复用语义，核对是否允许多路径、如何计部分完成 |
| 坐标、包名、XML/XPath | 按 NEXT 设备与 APP 版本适配，不能直接当鸿蒙可执行脚本 |
| 测试初态、账号、数据、日期 | 在实际手机复建并记录；能否重置要逐用例确认 |
| 鸿蒙执行后新轨迹 | 新建 attempt，保存实际手机原图、动作、异常与判分证据 |
| 调度/虚拟时间/隔离/崩溃恢复 | 保留项目自身工程测试，公开 GUI 任务不能替代这些验证 |
| 存档图转文 | 另选图做事实标注与描述质量核对；第三方模型的 thought 不能当作截图描述金标准 |

手机截图和后端真值不可得时，可组合 UI 可读状态、OCR、图像断言及人工复核；VLM 可辅助判定，但需留下证据和无法判定分支。规则可以允许多条有效路径，无需逐张像素比对参考图，也不必走完全相同的点击顺序。

原样在指定 Android 环境运行的结果，才可能按该基准官方口径比较；移植到 NEXT、改变任务或替换判分后，应报告为“基于某公开任务的鸿蒙适配集”，不能沿用公开排行榜分数。

## 6. 建议如何改进下一步测试

先在现有验证台补一小批有来源的任务，例如 8–12 条；这是建议规模，不是已确认交付量。首批优先可恢复、无需支付或公开发布的任务，覆盖基础操作、筛选/对象条件、多步条件保持和一两条跨 APP 活动。实际可执行数量由 NEXT 的 APP 可用性、初态和规则可观测性决定，不以凑够数量为验收目标。

建议按下面顺序组织同一任务，沿用现有页面递进关系：

```text
公开任务与原始规则
    ↓ 记录鸿蒙迁移差异、初态和版本
选用的任务实例
    ↓ 使用同一规则，分别执行候选
实际运行轨迹（动作、原图、调用、异常）
    ↓ 独立评判，不读取 Agent 的完成宣称作为真值
逐子目标结果与证据 → 同任务轨迹对照
```

每条记录建议分开保存以下状态；这是接下来实现时要落实的语义，并非声称页面现已具有：

| 维度 | 要回答的问题 |
|---|---|
| 运行状态 | 未开始、执行中、停止、异常还是正常结束？ |
| 动作状态 | 发出了吗、收到返回了吗、效果是否未知？ |
| 截图状态 | 是否获取/落盘/可解码/关联正确？是否缺图？ |
| 业务判定 | 各条件通过/失败/无法判断，完成了哪些，缺哪些？ |
| 评判来源 | 状态规则、OCR、VLM 或人工？对应哪一步、哪张图和哪版规则？ |

Agent 正常退出、图片保存成功、业务目标达成都应分别呈现。相同最终结果可以有不同有效路径；进程错误和证据缺失不能悄悄计为业务成功或在统计时丢弃。评价规则不要把后续答案或参考轨迹提前透露给被测 Agent。跨用户隔离、设备争用、持久化和虚拟时间继续由现有工程测试保障。

首轮先用规则/本地 OCR 和人工抽查校准判分；确需 VLM 再给评判请求单独预算，不因 MobiFlow 支持升级检查器就默认开启额外模型调用。先复用任务、证据格式和必要判分模块，再根据实际接入代价决定是否引入完整框架。

## 7. 本轮核对范围与证据

公开来源文本快照及任务目录位于 [output/benchmark_research_20261021](../output/benchmark_research_20261021/)，用于调研，不是已安装的运行组件。主要包括查看器配置/脚本、100 任务目录、任务 1/14 详情、规则 1/3、评分引擎与代码许可证。原文保留作复核，不在产品中执行。

浏览器读取回放页面有超时；本轮对查看器功能的结论来自实际 HTTP 200 的页面源代码、公开数据与评分规则，不冒充完整浏览器交互验收。搜索索引仍有旧 `Xiaomi-GUI-0` 路径，本机该旧站路径返回 404，实际核对使用用户给出的 `Xiaomi-GUI` 路径。

本轮没有运行第三方判分器、抽取误判率、操作手机、导入产品任务库或调用真实模型；已核对的事实与建议迁移方案分开列出。框架选型仍由用户决定。
