# 发布维护流程

首次发布目标：公开仓库 `rexyang97/BehaviorLab`；main为v0.4发布基线，v0.5保留开发分支。用户本次指令授权建立远程、上传项目与发布Release，替代此前仅本地管理限制；不改写或删除既有提交，不推送其他本地分支／内部标签。

1. 从已确认交接标签开独立发布分支，保留开发工作区。只整理发布和归档，不自动推进后续功能版本。
2. 检查准备推送分支的全部可达历史及当前文件；密钥、运行数据库、原始私人采集、依赖和输出包不进源码Git。测试截图仅作为审阅后的Release附件，不进Git。
3. 运行该版工程回归及必要离线契约；使用全新目录执行教程、解压与启动／停止，核对实际入口。分别说明API、浏览器、GUI双击及另一台电脑验证范围。
4. 从已提交源码构建新的干净包，固定运行时和框架版本。添加已审阅测试档案，生成文件哈希清单、ZIP与SHA256SUMS，不覆盖旧包。
5. 核对ZIP不含符号链接、密钥、私人数据库、控制文件及无关任务；图片／原始模型文本需完成公开范围核对。
6. 本地提交并创建 `v0.4.0-preview.10` 标签，将发布分支推至远程main，单独推开发分支。禁止 `--mirror`、`--all` 和强制推送。
7. 先创建GitHub Draft Pre-release并上传Windows包、测试档案及校验表；核对标签指向、附件文件名／大小／哈希、发布说明与教程链接，再发布。
8. 从公开地址匿名核对源码、Release状态和实际下载；下载后重算SHA256。完成后记录地址、提交、附件清单及尚未验证范围，不能把“已构建”写成“已发布”。

GitHub自动源码ZIP不含运行依赖和测试大图，用户应下载Assets。单附件需小于2GiB，超限应按可独立理解的组件拆包并写明关系，不能静默丢图。[GitHub说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。

维护者可用官方GitHub CLI创建仓库和Release；登录由维护者完成，不在仓库或教程里记录令牌。[CLI发布说明](https://cli.github.com/manual/gh_release_create)。本项目不默认运行云端手机任务，不因发布恢复原电脑的设备、真实模型或旧队列。
