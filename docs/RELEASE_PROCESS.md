## 冻结前

1. 核对 [PRD](PRD.md)、实际 [Spec](ARCHITECTURE.md)、[审查问题](CODE_REVIEW_V04_20261030.md) 与 [当前状态](CURRENT_STATUS.md)。确认功能范围、保留缺口和验收口径。
2. 文档、业务修复和格式整理分开审查；公共协议／数据变化应有版本与兼容依据。仅注释不伪造新真机成绩。
3. 离线工程、原生夹具、网页、真实GUI与目标电脑验证分别留证；未做的不写通过。演示任务定义不是业务完成证明。
4. 先处理或明确接受已知风险，特别是输入所有权与损坏证据；本轮未实现这两项修复。

## 获得当轮发布指令后

1. 只从 v0.4 发布工作副本冻结已核对提交，不带其他本地开发内容。
2. 检查整个待分发范围：密钥、私人库、运行数据库、无关任务与新运行不上传。已授权历史附件的授权不扩大到新增截图和 HiLog。
3. 在新目录从已提交源码构建，固定框架／运行时，保留第三方声明，生成完整文件清单和哈希。版本号应与新的正式发布记录一致。
4. 运行对应回归、依赖检查、全新目录部署／停止及必要界面核对；发布说明披露真实范围和未验证项。
5. 使用新标签与新附件，不改写 `v0.4.0-preview.14` 等历史标签，不替换旧ZIP。是否对外公开与许可证由项目负责人另行确定，本轮不擅自选择。
6. 发布前核对具体仓库、可见性、提交、文件名和SHA256；发布后核对实际状态和可下载内容。没有完成上传／下载核对，不能仅凭本地构建称已发布。

源码Git不保存数据库、依赖与大图，安装使用命名Windows包，Source code ZIP不带运行依赖。发布也不自动开始手机任务、模型、投屏或恢复旧队列。
