# v0.4 文档编写 Spec

标识 DOC-V04 / R2；2026-10-30；当前为内部协作规范。没有指定外部 spec 模板，本轮采用需求可追溯、契约明确、验收可核对的结构；不宣称遵循某个未提供的外部标准。

## 文档职责

| 文件 | 唯一职责 | 不应承担 |
|---|---|---|
| `README.md` | 项目定位、能力边界、快速启动与阅读导航 | 按时间堆叠所有历史，不维护第二份需求 |
| `PRD.md` | 背景、用户、场景、目标／非目标、Q/N编号需求、验收与风险 | 实现细节或把目标写成已交付 |
| `ARCHITECTURE.md` | 实际组件、调用链、数据归属、接口、资源和恢复边界 | 把未来分工说成现有模块 |
| `DEVELOPMENT.md` | 环境、独立启动、最小教程、测试层次与修改入口 | 私人路径、凭据或未经核对的命令 |
| `CONTRIBUTING.md` | 编码、注释、协作、提交与评审约定 | 假设尚未安装的 lint／CI 已生效 |
| `COLLABORATION_MODULES.md` | 三大模块职责、契约、文件归属、具体维护任务与独立验证 | 将方向确认写成重构已完成，或自动扩展业务 |
| `CODE_REVIEW_V04_20261030.md` | 审查范围、发现、复现、风险、处理与验证 | 用指标或测试通过给代码开无缺陷证明 |
| `CURRENT_STATUS.md` / `NEXT_TASK.md` | 当前事实／唯一下一步 | 从历史内容猜测当前授权 |

## 编写规则

1. 首段或元数据表写适用版本、文档修订、日期、状态与范围。
2. PRD 用 Q 编号表示功能，N 表示非功能，A 表示验收；实现文档引用编号，不复制整段需求。
3. 接口列输入、输出、来源、单位、可空值、所有权、错误、副作用与兼容；真实接口和建议接口分开。
4. 描述异常、取消、超时、并发、崩溃、损坏数据和恢复；不能只有正常流程。
5. 验收列触发条件、应观察结果、证据入口、实际验证层次。短文本、离线夹具、HTTP、网页、真实GUI、部署分别报告。
6. 需求与实际实现不同处写明差距，不删除失败样本；待确认项明确负责人角色与下一步，不替用户决策。
7. 图使用可维护 Mermaid 源码；“实际架构”与“目标分工”分图标注，不画不存在的服务。
8. 本地文件使用仓库相对链接，公开资源使用具体页面；不链接个人 `.data` 或输出密钥。
9. 当前页只给当前事实；版本历史由 Git、CHANGELOG 和发布记录追溯，旧日期数字不累加成新总数。
10. 文档变更检查链接、命令、需求映射与差异；纯文档不自动触发手机、模型或全量工程回归。

三大模块方向已确认：用户与行为规划、手机活动执行、整体中控平台。Spec分别标注组织方向、内部工程安排和当前实现，当前源码尚未据此完成重构。所有材料仅针对v0.4，不纳入其他本地开发版本或更换开发语言议题。
