# HOScrcpy 网页连续投屏

2026-10-23，preview.8。入口：[测试过程详情](http://127.0.0.1:4317/phone-lab#process)。这是独立的本机视频观察通道，不改变三候选框架的选型。

## 使用

1. 手机通过USB连接、允许这台电脑调试并保持解锁。在过程页点击“开始投屏”，等待出现“H.264 连续视频”和已解码帧数。
2. 如需观察测试，先接通投屏，再启动单项或组合评估。视频只观看，不提供鼠标反控，也不计作模型请求、动作或任务证据截图。
3. “全屏”放大手机画面；“停止”、切换到任务/结果页、关闭网页或暂停真机操作会释放查看会话。多个查看页共用一个编码进程，最后一个关闭后停止SDK。
4. 断线会显示提示，不自动重放手机动作。检查数据线、USB授权和解锁状态后重新点击“开始投屏”。刚停止时需等待后台释放。读取目录/状态或打开页面不会自动启动采集。

不需要打开DevEco Testing/Studio窗口，也不需要浏览器选窗。画面通过HDC、Java后台和本机HTTP进入网页，使用浏览器MediaSource解码。没有截图轮播、浏览器屏幕共享、音频采集、自动录像或视频上传。SDK初始化会部署/连接自己的设备端服务、调用唤醒与创建HDC转发，因此启动/停止仍属于真实设备操作。

## 本机安装与换电脑

必需：项目要求的Node.js24、可用HDC、已授权的手机、带javac的JDK17或更高版本，以及支持H.264/MediaSource的Edge或Chrome。当前电脑使用既有工具目录中的Temurin21.0.8+9；只运行java后台，不打开该工具界面，不改全局JAVA_HOME。

项目目录中执行：

```powershell
node scripts/hoscrcpy-setup.mjs --install --java 'C:\你的JDK目录\bin\java.exe'
node scripts/hoscrcpy-setup.mjs
```

也可预先配置自己的JAVA_HOME再执行`--install`。显式安装会从原项目公开Release下载固定JAR并校验大小/SHA256，再编译本项目的Java桥。第二条仅检查；两条均不连接手机、不调用模型。修改Java桥后需重新安装编译。JAR、编译产物和本机路径位于被Git忽略的`.runtime/hoscrcpy`。

HDC沿用`HDC_HOME/PATH`或项目`.runtime/device-tools.json`。SDK路径、设备号、端口和命令不允许从网页提交。投屏实际启动前要求唯一可见设备，并重新校验SDK哈希。组件缺失不会影响历史轨迹/结果查看。

2026-10-23的preview.8 Windows干净包已带JRE、视频SDK和预编译桥，新电脑使用该包无需执行上述安装命令，先运行03_CHECK.cmd即可。2026-10-22旧包仍为preview.6，不含本次功能。源码开发或修改桥仍需JDK17+重新编译；仅搬移原开发目录时，若配置了外部JDK绝对路径，需重新设置。未验证第二台物理电脑，不声称已完成跨机视频验收。

## 固定版本与架构

- [HOScrcpy原项目](https://gitcode.com/OpenHarmonyToolkitsPlaza/HOScrcpy)的Java SDK后台采集路线与仓库`web_demo`一致；本项目将传输改为本机HTTP二进制流，不启用其反控接口。调研源码提交`cf6603b38586d457801ee93203e1a09a846b943e`。README中的旧SDK版本不作为本次安装版本。
- 公开Release `v1.0.16-beta`中的SDK为`hosScrcpy-1.0.18-beta.jar`，18,442,278字节，SHA256为`2ce60b1893cc2be471a8cd7eab7e4127e41921f1f89a32a134c730ba15c8c0fd`。JAR只存本机，不纳入Git或当前干净包。
- 当前手机使用`setForceUseMobileSo(true)`，即系统内置扩展。捆绑扩展首次探测未出帧；切换系统扩展后收到SPS/PPS/IDR和后续帧。当前参数：缩小2倍、15fps上限、4Mbps目标码率；不是实测稳定15fps，静态画面可能降帧。
- 网页固定使用本地JMuxer2.1.4及MIT许可，来源和校验见[播放器说明](../web/vendor/README.md)，无远程脚本。

| 模块 | 职责 |
|---|---|
| `integrations/hoscrcpy/PhoneVideoBridge.java` | SDK采集、二进制分帧、关键帧请求、停止；日志不混入视频 |
| `src/phone-video-runtime.mjs`、`scripts/hoscrcpy-setup.mjs` | 固定依赖、完整性检查与显式安装 |
| `src/phone-video.mjs` | 单编码会话、最多4个查看页、启动/回收互斥、慢客户端关闭、脱敏诊断 |
| `web/phone-video-protocol.mjs`、`phone-video-ui.mjs` | 分帧校验、MediaSource播放、开始/停止/全屏与离页释放 |
| `tests/phone-video.test.mjs` | 协议、权限、生命周期、失败回收及比较隔离的离线替身测试 |

只监听127.0.0.1；启动/停止要求同源写入头，视频使用短期随机令牌放请求头，令牌与设备号不出现在URL或目录状态中。视频只在内存有限缓存，不写录像；SDK诊断与包数/字节数留在本机忽略目录`.runtime/hoscrcpy/sessions`。这些诊断不等同于任务执行轨迹。

## 实机验证与限制

当前手机SGT-AL10，OpenHarmony-7.0.0.105，API26，原屏1320×2848，浏览器解码660×1424。首次流解码125帧后因gRPC网络关闭断流；当时HDC连接状态波动，不能据此断言是熄屏导致。重新确认USB后，下一次会话持续约174秒、收到82包/612,055字节，网页解码61帧；布局读取、左右各一次桌面滑动与画面同步通过，随后主动停止回收成功。再一次重连出帧，切换页签自动回收通过。正式入口另一段会话持续约559.7秒、1,780包/9,325,787字节，已在网页观察至少241个解码帧、配置测试保持播放及全屏；后续出现相同网络关闭异常。断流根因未确定，不能记为长期稳定通过。最新重连/停止验收见[脱敏记录](evidence/20261023-hoscrcpy/acceptance.json)。真实手机图片只存本机忽略的`output/hoscrcpy_20261023`。

上述验证证明本机网页直连视频和公共HDC操作可以共存，不是三框架带模型业务任务的成功验证，也不是长期稳定性或性能基准。本轮真实模型请求为0，原39运行/6任务/3服务和36项成绩不变。后续需在实际使用中观察长时间运行、不同系统/设备、三框架完整任务期间的资源占用与异常断线。

新运行在冻结输入中保存`video_observation_at_start`，说明启动时是否已投屏及参数；打开或关闭视频不会改写旧结果。自动可比性分组区分启用视频的运行与旧/未启用视频的运行，避免把观察开销混为同一条件。该字段只表示启动时状态，不保证整段持续在线；断线以实际观察和本机SDK诊断为准。
