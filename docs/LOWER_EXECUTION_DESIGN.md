# 下层执行 Agent：活动到手机操作

版本：v0.5 讨论稿 · 2026-10-19。本文并入总体技术方案第 8 节，细化此前尚未解决的核心执行问题。以下是工程建议与待验证假设，不是已实现功能或已确认的全部业务要求。当前执行器仍为 Mock。

## 1. 核心问题与推荐路线

目标是让一个每日活动在动态页面上形成可恢复、可核验的实际操作。推荐“活动级滚动规划、单步观察执行、基于证据更新进度”，再根据实际收益加入操作技能。下层先规划子目标，操作坐标与具体对象根据当前页面决定，不预编整段点击脚本。

两层业务边界保持：上层选择用户当天做什么以及活动后的调整；下层自主解决当前活动怎么做。下层内部的分解、定位与核对是执行职责，不新增一层用户行为规划 Agent。管理程序保存状态、调度与校验，不能代替模型选择行为内容。

## 2. 活动委托契约

现有 task 字段继续兼容；建议补充以下语义，具体字段名和版本在真实接入时定稿。下层可解释委托、发现歧义，不能自行改写上层硬约束。

| 内容 | 示例活动中的含义 | 谁决定 |
|---|---|---|
| 目标与对象量 | 在大众点评了解三家不同餐厅并比较 | 上层 |
| 硬约束 | 城市、APP、不能改变的限制 | 上层或运行前指定 |
| 软偏好 | 根据人设考虑菜系、预算倾向和距离 | 上层提供，下层用于候选选择 |
| 完成证据 | 每家有详情证据，价格、位置、评价各有观察来源 | 接入前约定，上层可指定活动需求 |
| 自主范围 | 搜索表达、排序、候选替换、普通页面弹窗处理 | 下层在边界内决定 |
| 升级条件 | 只有放宽硬约束、改变活动目的或换 APP 才能继续 | 下层返回受阻/部分结果，由上层决定调整 |
| 操作预算 | 最大步骤、无进展次数与真实耗时上限 | 工程配置，数值待实测 |

预算控制运行成本，不规定用户每天做什么。遇到目标本身不可能或证据不足，允许 partial/blocked，不能用加工文字补足实际任务完成量。示例餐厅场景不是首个 APP 的既定选择。

## 3. 内部模块与输入输出

| 模块 | 输入与输出 | 关键边界 |
|---|---|---|
| 委托解析与约束检查 | task/persona/能力范围 → 明确目标、硬软约束、歧义 | 不将歧义猜测变成事实；缺必需信息时返回明确原因 |
| 滚动子目标规划 | 活动状态与当前观察 → 子目标、完成条件、当前子目标 | 保存短期逻辑路线，优先局部修订；不重排每日计划 |
| 观察与页面定位 | 图像及可用 UI 信息 → 页面类型、候选元素、对象与位置 | hipyum 有 UI 树才使用；仅有截图时走视觉定位 |
| 动作决策与校验 | 当前子目标、页面、工作状态 → 意图、动作、预期效果 | 程序校验范围/参数/预算，模型决定具体对象与操作 |
| 工具适配与记录 | 规范动作 → hipyum 返回与原始观察 | 动作前落意图，每张图均留存，超时不表示未发生 |
| 效果核对与进度归并 | 前后观察、工具结果、预期效果 → 成功/失败/未知及证据 | 不只接受执行器自报成功；未知不计作完成 |
| 恢复与结束判定 | 持久化事实、当前页面、失败历史 → 继续/局部恢复/终态/需关注 | 不盲目重放副作用；终态结果再反馈上层 |

首版可以一个 GUI 模型承担规划、操作与核对角色，用不同结构化调用区分职责；不要求三个模型或独立进程。常规步骤先做程序检查，在子目标完成、操作效果不明、停滞时加强视觉核对；减少无必要的重复推理。

## 4. 活动工作状态与检查点

| 状态组 | 建议内容 | 恢复时用途 |
|---|---|---|
| 活动身份 | user/activity/attempt、委托版本、约束快照 | 防止恢复到其他用户或旧目标 |
| 子目标 | 稳定 ID、依赖、状态、当前项、完成证据引用 | 确定下一目标，保留局部修订历史 |
| 对象账本 | 已访问对象、已获取字段、缺失字段、证据、身份不确定性 | 去重、补信息、计算真实对象量 |
| 观察快照 | observation_id、截图引用、页面、尺寸/方向、环境 | 判断定位是否仍然有效 |
| 动作状态 | action_id、前置观察、意图、工具请求/返回、预期效果 | 分清未发送、已发送、已核验与效果未知 |
| 失败与预算 | 已尝试路径、同状态重复、耗时与剩余预算 | 避免循环，决定局部恢复或结束 |

子目标可采用 pending/active/verified/blocked/superseded；这些是建议新增的内部状态，不复用外层活动的 completed/partial/blocked 含义。只有证据核对后才将子目标 verified。新状态提交应关联相应步骤/截图与修订来源。

每次模型输入携带当前子目标、必要约束、结构化进度和少量相关观察；完整轨迹留在存储，可按需读取，不把全部原图与历史对话无限追加。工作状态仅服务当前活动，不提取长期偏好。共享技能只保留通用操作知识，不吸收其他用户的搜索内容或偏好。

## 5. 单步闭环和复杂任务的推进

总体技术方案的 S4 时序图描述完整调用。每轮先读取当前状态和观察，必要时生成或修订子目标，再决策一个动作。校验定位所依赖的 observation_id、屏幕尺寸和参数；页面变化后旧定位失效。工具执行前保存意图，执行后保存所有实际返回与图像，再核对预期效果并更新状态。

对子目标的前置条件和结束条件进行显式检查。例如“进入餐厅详情”是导航子目标，“获得三家餐厅的比较信息”是信息目标。导航成功不能直接满足信息目标。判断加载完成可结合页面变化与可见状态；不能把固定等待时间等同于页面已经就绪。

| 示例阶段 | 下层的自主处理 | 完成证据或分支 |
|---|---|---|
| 首页出现定位弹窗 | 处理普通弹窗并核对城市 | 城市与活动约束相符 |
| 搜索候选 | 选择搜索表达、排序与可用筛选 | 实际出现候选；约束没有偷偷放宽 |
| 查看一家详情 | 按需进入价格、位置与评价区域 | 所需信息各有关联图；未知字段显式保存 |
| 返回列表，排序已变 | 重新观察和定位，不沿用旧坐标 | 新动作依赖新观察 |
| 多家对象比较 | 对象账本去重，按缺项补看 | 不按点击数或截图数累计对象量 |
| 第三家信息不足 | 补充页面或换候选 | 不因打开详情就视为比较完成 |
| 无足够合格候选 | 保存已完成部分并结束反馈 | 上层决定是否放宽条件或调整剩余日程 |

子目标可以包括顺序、条件分支、遍历多个对象和局部回退；首版可采用简单依赖表，不急于建设通用工作流语言。每次只对受影响的子目标修订，避免失败后整段从首页重做。

## 6. 完成证据与核对机制

每项完成主张建议保存 claim_id、对象/子目标、判断、evidence_refs、核对方法和未解决问题。程序检查数量、关联、去重和硬约束；视觉模型核对页面语义。模型核对输入应包含原始观察与工具返回，不能只看执行器摘要。同模型分角色调用也不能保证独立正确，需要人工抽样与外部可核验样本评估。

| 主张 | 足够/不足证据的区别 | 处理 |
|---|---|---|
| 点击成功 | 工具收到点击与目标页面出现是不同事实 | 两者分开保存 |
| 已收藏 | 点击图标不足；需要收藏状态或列表变化等证据 | 不明则标 unknown |
| 比较三家对象 | 三张截图不足；要关联三个不同对象及要求的信息 | 对象身份不明时不宣称精确去重 |
| 已读文章 | 页面出现不能证明人类认真阅读 | 描述可观察行为；若要求浏览段落，另定操作性标准 |
| 任务完成 | 子目标与硬约束均有足够证据 | 否则返回 partial/blocked 和缺项 |

对象有可靠 ID 时优先使用；没有 ID 时可结合可见名称、地址等线索做活动内身份匹配，并保留不确定性。不得构造一个看似稳定的内部编号后就宣称已经证明对象唯一。

## 7. 操作技能与经验复用

建议先复用搜索、筛选、进入详情、查看评价、返回列表、核对收藏状态等短技能。技能至少有 app/version、适用观察、前置条件、参数、步骤策略、预期效果、失败退出条件和来源。技能执行仍记录每一步和每张图；不能因为合并为高层动作就跳过采集。

技能只是可检索的操作办法，下层根据当前页面决定是否采用。可由人工示范和成功轨迹提出候选，经复查和不同初始页面回放后启用。先验证无技能闭环，再对比有技能的成功率、步骤数、费用和恢复表现。APP 更新、页面不匹配或效果核验失败时退出技能，不强行套用。

能力目录限定能做什么，技能库帮助怎么做，研究用例负责怎么测。上层仍自主决定当天活动。AppAgent 的示范/探索文档和 AppAgentX 的重复操作抽象提供参考，但不构成项目必须实现经验自学习的要求。

## 8. 失败、恢复与上层边界

| 失败类型 | 下层优先处理 | 何时结束或升级 |
|---|---|---|
| 页面未加载/普通弹窗 | 有界等待、重新观察、处理允许弹窗 | 反复无进展或预算不足 |
| 定位失效/误入页面 | 从新观察重新定位，局部返回 | 无法确定当前环境 |
| 搜索无结果 | 在原约束内换搜索表达或候选策略 | 需要放宽硬约束 |
| 对象信息不足 | 补看或换对象，保留已有证据 | 不能达到数量或证据要求 |
| 动作超时 | 查询当前可见状态，核对是否已发生 | 无法判断副作用，不自动重发 |
| 进程中断 | 从最后落盘动作、观察与工作状态恢复 | executor.recover 不授权则 needs_attention |

以收藏为例，超时后再次点击可能取消收藏，因此应先核对当前状态。截图生成与动作结果之间的时间窗也可能造成不确定。不能承诺跨 hipyum 与数据库的 exactly-once。建议动作前后持久化检查点，保留证据缺口；真实 API 的请求查询与幂等能力需另行确认。

当前外层调度在活动终态后反馈。首个接入仍通过 partial/blocked 返回需要业务调整的原因，不擅自新增活动执行中的同步上层对话。若未来确有必要，再单独设计 ask_upper 协议、暂停状态与恢复语义。

## 9. 实时视觉与存档 VLM

实时视觉在执行关键路径：理解当前页面、定位、核对效果。存档 VLM 在活动结束后按序处理每张图，产出研究观察文字，仍与后续活动独立推进。两者可共享服务，但区分 purpose、提示版本、来源与输出类型。实时模型输出不自动填充为最终原始描述；若以后复用，需要明确兼容性和来源规则。

活动工作状态只保留执行所需信息。不能等待全部存档描述才推进每一步，也不能为省调用省略应留存的图像。端云部署分别实测，采集主机本地不等于手机端侧。

## 10. 接入与验证顺序

| 阶段 | 做什么 | 观察指标 |
|---|---|---|
| A 工具与记录 | 一个 APP，验证截图、输入、点击、返回与动作关联 | 时序、坐标、返回语义、每图留存、超时行为 |
| B 基础闭环 | 单对象搜索浏览，验证观察—动作—效果循环 | 成功率、定位失败、无进展、误报完成 |
| C 复杂任务 | 多对象比较、筛选、信息补充与允许的状态变更 | 去重、字段证据、子目标修订与实际完成量 |
| D 恢复对照 | 在意图后、发送后、核验前注入中断 | 重复副作用、恢复成功、人工接管与数据缺口 |
| E 技能对照 | 同任务同环境，对比无技能与短技能 | 步骤、费用、耗时、成功率及错误泛化 |

成功率之外，应记录误报完成率、完成主张证据覆盖、对象重复计数率、循环停滞、恢复后的重复副作用。样本数、阈值和预算数值由首次真实试验确定，不预先承诺。

## 11. 现有接口复用与未实施清单

沿用 executor.execute/recover 与 recorder.beginStep/capture/finishStep，以及外层 saveResult 后 adjust 的顺序。建议新增活动工作状态、子目标修订、对象证据和核对主张的持久化实体；字段与迁移尚未实施。原始事实仍以现有步骤、图像和结果关联为基础，不用模型摘要覆盖。

初始观察当前必须关联步骤，真实接入要明确 observation 步骤如何先 beginStep 再 capture，不能凭空写无步骤截图。实际动作的截图阶段与多图关联依赖 hipyum 契约。设备全局锁、账号环境与模型装配也仍待实现。

首轮不增加分布式系统、通用行为库、经验自动自学习或全年行为脚本。先核对 hipyum、首 APP、模型服务和可复用下层代码，选定同一批基础/复杂/恢复任务做真实验证。
