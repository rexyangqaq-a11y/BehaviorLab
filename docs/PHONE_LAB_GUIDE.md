## 执行与暂停

四阶段队列已经完成，当前没有活动任务。运行新测试期间不要手动操作手机、另启任务或重启后台。需要使用手机时点击“暂停真机操作”，会停止活动任务并持久阻止后续设备准备/模型运行；已有证据仍能查看、审核和下载。恢复本身不会重放旧任务，未知动作效果须先独立核对。

## 自定义任务

1. 在“任务列表”新建或编辑任务，填写名称、目标应用、任务说明、判定要求和禁止操作。内置五题内容只读，但可以配置起点或复制为自定义任务。
2. 起点只选一种：“选择已有起点”按名称选以前保存的状态，可预览；或先把手机摆好，选择“使用手机当前状态”，填写起点名称。无需填写起点类型、应用包名或页面说明。
3. 点“保存任务设置”一并保存任务与起点关联。选择已有起点不操作手机；当前状态会截图并保存布局，不复位、不打开应用、不调用模型。任务内容保存成功但起点失败时明确提示，不能当作配置已完成。未保存的编辑不会跨刷新保留。
4. 命名起点可跨任务复用，任务改名/编辑后也可继续沿用；历史起点复用时保留原文件，创建有来源引用的独立副本。已有运行的输入与结果不变，旧版本编辑冲突仍拒绝覆盖。
5. 在“测试 → 单项测试”选择框架、模型服务和任务，可填写测试名称，留空默认任务名。组合评估可多选并命名，起点均自动沿用，无需再次选择/命名。默认15请求、40框架动作、600秒、512输出tokens，零重试。
6. 开始后先核对手机实际状态，再允许模型请求；实时轨迹、回复与用量在过程页查看，结束后到结果页独立判定。“框架已结束”不等于任务通过，通过判定须关联真实截图。停止保留记录，不自动重试或回放。

## 组合评估与本轮四阶段队列

在“测试 → 组合评估”三个维度均可多选，按框架×模型服务×任务展开全部单元，显示实际数量。首次切换默认沿用单项选择，可分别全选或清空；一批最多150个测试单元，这是队列规模限制，不是总请求限额。每个任务自动使用任务中配置的当前版本基准，测试页无需再次选择，可填写评估名称。

队列启动时冻结任务与起点，后续修改设置不改变已启动批次。命名桌面起点每单元可自动回桌面并核对；其他命名页面自动核对当前状态，不反复要求配置或确认。任一命名起点不匹配即保存受阻原因并停止后续单元，模型请求前阻断，不把命名或截图当作已恢复页面。旧协议保留兼容路径。新v9路径经过离线验证，本轮未启动真实手机任务。

已经完成的四阶段队列由 `scripts/phone-evaluation.mjs` 执行：单配置四题 → 单框架三模型计算器 → 三框架临时最佳模型计算器 → 四题九组合。已有相同单元直接复用，避免重复；不要因界面调整重启旧队列。第二阶段经独立结果判断选出临时比较模型，最终框架仍由用户确认。

四题包名/版本已在本机核对，均从手机桌面起点，框架自己打开 APP。准备只停止目标 APP 进程并返回桌面，不清账号或数据。用户明确“不用完全一致”，时钟、小组件内容和最近应用顺序允许变化并留证；同手机、桌面页面、方向和可操作状态须相同，不追求像素完全相等。APP 内部历史/动态结果未做镜像还原，不能声称完整状态一致。

默认单题单组合15请求、40 SDK动作、600秒执行段、512输出tokens/请求、0自动重试；整批请求总上限为null。请求可能用于观察、校验、规划或结束，一次回复也可能包含多个动作，框架还可能在动作前后拍图，因此请求数、动作数和图片数分别计量。界面可调整单次限制，不同限制不混算。本轮为36个唯一评估单元，进度见[真实结果](PHONE_EVALUATION_RESULTS_20261022.md)。

## 查看、对比和导出

结果页默认查看已完成的36单元批次。运行记录按页显示（默认每页12条），包含任务、执行手机、框架/模型、业务判定及耗时/请求；窄屏显示记录卡片。“组合对比”用框架×模型为行、任务为列，点击单元格进入具体运行。列表与矩阵互斥显示，不同时重复铺表。

单次详情替换结果列表，可返回并保留筛选/分页，或直接看上一条、下一条。详情分为“截图与模型回复”“判定与环境”“原始记录与导出”。手机型号在标题中，完整系统全名、产品软件版本、API、截图尺寸和应用版本在环境中。优先读取该次执行保存的环境；只有起点信息时明确标为起点记录，缺少字段显示未知，不用当前手机信息覆盖历史。

截图区新增“截图与模型判断”。切换图片即可查看关联请求的模型计划/日志等原始返回字段、框架实际动作、耗时与用量；展开“完整模型回复原文”阅读未经改写的内容。可以跳转到实际提交的模型缩图，或切换“全部图像”查看动作前、框架观察及模型输入等资产。没有动作的请求也保留在“按请求查看全部”中，不因只看动作图而遗漏。

图文关联分成：精确图像引用证明的实际提交、动作所依据的回复，以及截图前后按日志顺序关联的回复。原图不自动视作模型输入，最终截图在框架结束后采集，不能据此声称此前模型已看过终图。缺少回复时不补写判断；这些展示均只读已有日志，不新增模型调用或手机操作。

“结果与对比”保留真实任务历史及审核状态。正式对比按协议、用例、指令、框架版本、模型、起点比较键和限额分组。早期网页验收成功记录未使用最新协议，保留在历史表中，不进入正式比较分组。没有可比记录时直接显示无记录，不用 Mock 填数。

可同时筛选框架、模型、任务、手机型号、独立判定、执行阶段、评估批次，并搜索任务名称/ID。列表和对比表同步应用所有条件，筛选不会调用模型或操作手机；“清除筛选”恢复全部记录。查看本轮完整矩阵应按评估批次筛选；“④完整矩阵新增”只显示第四阶段新执行单元，前面已测复用单元仍归原阶段，不重复计数。运行中自动刷新会保留已选条件。

“导出完整记录 JSON”包含完整输入、环境、版本、事件、用量、审核及资产引用；“下载含原图的证据包”包含 JSON/JSONL、本机原图和原生日志。运行中暂不生成 ZIP。截图下载时核对哈希。JSON 不嵌入所有图片字节，完整离线复查应保存 ZIP。原图/布局可能含账户显示名、序列号等个人信息，导出是本机下载，不自动上传第三方。

真实数据目录：`.data/.phone-lab/starts/<ID>/`、`runs/<ID>/`、`batches/<ID>/`；自定义任务为 `tasks/task_<UUID>.json`，任务基准关联为 `task-startpoints.json`。新运行协议为 `phone-lab-v9-named-start-v1`，此前v4–v8结果与原文件保持不变。原始结果不被审核覆盖；最新审核单独保存，历史审核事件追加到 JSONL。模型密钥不进入上述产物；现有模型凭据 SQLite 为本机保存，未加密，不能将“本机保存”写成全量密文存储。Huawei 账号是另行保存的 DPAPI 密文，不用于测试工作台的模型调用。

## 部署与离线检查

本机三框架已安装。Midscene 局部依赖位于 `integrations/midscene/`；两个 Python 框架源码在 `.runtime/frameworks/`，客户端环境在 `.runtime/python-phone/`，均不进入 Git。Python 是这两个候选及 ZIP 导出工具的依赖，不是主工作台/Mock 启动依赖。

```powershell
# 只检查已安装版本及原生离线契约；不连接手机、不调用模型。
node scripts/phone-frameworks-setup.mjs --out output/phone-framework-deployment-recheck.json

# 软件回归使用临时数据、替身响应和本地 HTTP，不消耗模型额度。
node --test tests/*.test.mjs
```

`--out` 拒绝覆盖已有文件，复查时使用新文件名。新电脑需先安装 Midscene 的锁定依赖和 Python，再使用 `node scripts/phone-frameworks-setup.mjs --install --python <Python路径> --out <新报告路径>` 安装两个官方固定提交及客户端依赖。`--install` 会联网下载；未打包可迁移运行环境，不承诺复制源码即可真机执行。现有 HDC 为项目局部安装，不改全局 PATH。

关键实现：`src/phone-lab.mjs`（服务与整批调度）、`src/phone-tasks.mjs`（本地任务与版本）、`web/phone-test-plan.mjs`（三维组合）、`scripts/phone-lab-worker.mjs`（隔离执行）、`integrations/phone-frameworks.py`（原生 Python 桥）、`src/phone-device.mjs`（设备与图像）、`src/phone-startpoints.mjs`（起点契约）、`src/phone-evidence.mjs`（证据）、`web/phone-lab.*`（界面）。
