# v0.5 头脑风暴：单活动怎样接入主调度

日期：2026-10-25。状态：第一轮讨论记录；建议尚未全部获得用户确认。本轮先形成需求与概要设计，不修改业务实现。

起点：`codex/v04-handoff-20261025`（`3a2672d`）。依据为根目录协作规则、[当前状态](CURRENT_STATUS.md)、[下一任务](NEXT_TASK.md)、[版本计划](VERSION_PLAN.md)及现有源码。本文不新增外部框架调研或真实试验结论。

## 1. 先把问题说具体

v0.4已经证明独立工作台能运行三种框架，但主系统还没有把一个活动交给它们。v0.5首先要回答：主调度派发的究竟是哪项活动、用了什么组合、实际核实了几个对象、哪里中断、恢复会不会重复操作。

贯穿示例暂建议为：一个手工活动要求浏览2个符合条件的对象；夹具核实对象A，再打开A，随后找不到第二个对象。实际完成量为1，结果为`partial`。这比“框架说完成了”更能检验接入是否保留事实。示例是合成工程场景，不是新增手机成绩。

已经确定的边界：保留三框架与模型接口、用户改选优先；先做离线；手机和真实模型继续暂停；旧Mock可恢复；未知效果不自动重放；描述失败只补已有图。真实上层、人设生成、存档VLM、长期记忆、百对象与跨APP去重不进入本轮。

## 2. 接入路径可以怎么选

| 路径 | 优点 | 代价与问题 | 讨论建议 |
|---|---|---|---|
| 主调度调用phone-lab创建一条测试运行，再轮询结果 | 看似能快速复用现有入口 | 两套任务、状态、证据与恢复所有权并存；工作台技术结束没有主系统对象完成语义 | 不作为主接入方式 |
| 抽取公共运行保护，主系统与phone-lab分别调用，框架仍走注册适配器 | 复用原生循环、运输和保护；活动事实由主系统保存 | 要逐步拆出worker内的公共逻辑，做两条链的回归 | 推荐 |
| 为主系统重写一个通用手机Agent | 接口完全可控 | 重复实现已验证循环，扩大范围，也偏离保留框架的决定 | 不进入v0.5 |

推荐路径只统一必要的装配、设备排他、动作记录、限额和证据接口，不先建设通用插件平台。独立phone-lab继续拥有自己的任务、矩阵与审核页面，主系统继续拥有日调度、活动结果及上层反馈。

## 3. 完成量从哪里来

有三种可能：相信框架返回数字、按打开次数累计、按符合条件且有证据的唯一对象累计。前两种都无法处理“打开A两次”的示例，建议采用第三种。

最小台账记录对象身份、条件核对、完成证据和对应步骤。标题或截图哈希只能作为身份线索，不能通用于所有APP。身份无法可靠确定时，保留候选证据、暂不增加完成量，也不补造一个稳定ID。

离线先用明确对象ID的夹具验证账本行为。首个真实APP的身份提取与阅读完成条件另定：看到详情页、停留一段时间和真正读完是不同口径。工程层保证计数规则一致，不能凭规则存在就声称已自动理解所有页面。

## 4. 效果未知时，怎样让系统停在正确位置

动作意图已保存、命令已经返回、页面真的达到目标，是三个不同事实。进程在动作发送附近退出，系统通常无法证明“尚未发送”。缺少返回不能作为重发依据。

建议把`needs_attention`作为需要处理的运行状态，另存已核实完成量、未决动作和原因；它阻止继续调度，不伪装成普通业务终态。恢复先核对冻结配置、步骤和对象台账，再由执行器决定继续或要求关注。未知效果优先于“已完成1个所以partial”的普通结束规则。

人工处理有两个范围选项：

- 最小范围：只展示未知效果和证据，允许安全结束；暂不提供继续执行。
- 推荐范围：记录“已发生／未发生／仍未知”及依据，再单独选择继续或结束。复核本身不发动作；“已发生”也不自动证明对象已符合全部完成条件。

第二种更便于调试，但需要处理重复点击、审核版本冲突和进程是否仍在执行。用户尚未答复时，需求文档把它列为建议项，不把交互细节写成已确认要求。

## 5. 离线是不是只测一个假的适配器

建议分三层，避免测试名称混淆：

1. 装配与故障夹具：主调度进入统一执行器，工具和模型全为注入替身，验证持久化与恢复。
2. 原生框架离线契约：具备安装依赖时，通过现有注册入口运行合成图和固定回复，验证原生循环与公共接口；依赖缺失明确跳过。
3. 真实单活动：用户另行恢复后，才在指定手机、APP、模型和预算下验证。前两层通过不能代替这一层。

三框架都需要验证选择、装配和来源冻结。某框架不支持安全恢复时，可以返回`needs_attention`，不要求虚构原生会话续接能力，也不能偷偷切到另一框架。

## 6. 用户从哪里操作

建议在现有仿真任务详情增加“单活动调试”，沿用用户库／仿真任务／系统设置三个主入口。它显示待执行活动与冻结组合、当前观察和动作、目标与实际数量、重复和未核实对象、结束原因、执行／反馈／描述／导出各阶段。

“调试一个活动”只允许执行主调度当前可执行的一项活动；页面筛选不允许跳过前序活动。离线用例放在该入口的工程测试区域，不能混入真实运行成绩。首次真实测试恢复不由“保存配置”或“打开调试页”触发。

## 7. 本轮建议收敛

| 议题 | 建议 | 状态 |
|---|---|---|
| 架构 | 公共运行保护＋主系统执行器桥接，保留原生框架 | 工程建议 |
| 首个夹具 | 通用浏览，2目标／1实际／重复A | 已询问用户，暂按此写示例 |
| 去重 | 活动内可靠身份去重；不确定身份不计数 | 保守设计建议，真实APP口径待定 |
| 未知效果 | 持久化工作状态，阻断后续调度；提供最小人工处理 | 不自动重放已确认；交互范围待确认 |
| 实施顺序 | 装配与旧Mock兼容→证据台账→故障恢复→任务内界面→原生契约 | 工程建议 |

首个真实APP、真实对象完成条件、恢复时间和额度、正式包更新时间仍待决定。这些不阻塞文档与离线基础实现。
