# PPTX 固定生成规则

记录日期：2026-10-20。通过工作区根目录 `AGENTS.md` 引用，作为本项目后续 PPTX 生成、编辑与导出的常驻约束。用户后续的明确指示优先。

## 已确认的格式约束

### 1. 画布与字号使用正常的物理比例

- 使用 PPT 的物理页面尺寸设计，不能将高清图片的像素宽高直接当作 PPT 画布，造成画布过大、字号数字大而整页显示很小。
- 字号使用实际 pt，区分 CSS px、pt 与页面尺寸。预览时同时检查整页可读性和字号数值。
- 编辑现有 PPT 时保留原尺寸；用户要求等比缩放时，画布、字号、对象和布局相关的绝对长度一起缩放。保留宽高比，不拉伸内容。
- 用户关于“自己电脑上 21 号字已能当标题”的反馈是对尺寸和视觉比例的要求，不应升级成“所有标题固定 21 pt”。

### 2. 原生对象可编辑，普通形状允许组合

- 文字、模块框、表格和连接线使用对应的原生可编辑对象。表格保留原生表格，不用图片或大量文字框模拟。
- 普通形状、文本框和连接符不得带有禁止组合的限制。检查实际导出结果，不能只检查源代码；例如普通对象的 `noGrp="1"` 或 `noGrp="true"` 不得残留。
- 分组后仍能按正常方式取消组合和继续编辑。不要为绕过检查而将整页转成图片。
- 原生表格与占位符有 PowerPoint 自身的组合限制，不得将这类限制笼统归为所有形状都不能组合。不要擅自把用户要求的原生表格转成形状来规避限制。

### 3. 同一段文字使用一个文本框

- 一个自然段或完整说明，即使显示为多行，也必须放在同一个文本框中。
- 通过文本框内的自动换行、软换行或段落实现多行，禁止为了控制三行排版而生成三个独立文本框。
- 完整文本框内可以有多个相关段落；段内不同格式通过富文本设置，不能因为字体、颜色不同就拆散一句话。
- 独立标题、不同模块或表格单元格可以使用各自的文本容器。
- 编辑用户已修改的文件时，未经要求不自动合并、拆分或重排其已有文本框；本规则必须用于后续新增与重做的内容。

### 4. 多段箭头使用单个原生箭头或连接符

- 一条带折点的箭头必须是一个原生可编辑的折线／肘形箭头连接符，或一个能表达完整路径的原生箭头对象。
- 箭头头部使用该对象自身的端点样式。禁止用多个直线段和独立箭头／三角形拼出一条箭头；把这些碎片组合在一起也不算满足要求。
- 更复杂的路径仍应保留为一个对象，折点和路径可以整体编辑。能使用原生肘形连接符时优先使用；有明确节点时尽量绑定连接端点。
- 导出后检查实际对象结构和编辑行为，不能只依赖图上看起来相连。

### 5. 虚线使用对象自身线型

- 虚线、虚线箭头和带折点的虚线箭头，使用同一个对象的原生虚线线型。
- 禁止用大量短线段模拟虚线；也不能将虚线折线路径拆成一组短线再拼接箭头。
- 线宽、虚线样式与箭头端点一起保留在原对象上，便于用户统一改色、调粗和移动。

### 6. 表达、修改范围与交付

- 用自然、具体的中文，避免口号和含糊的术语。保留用户已经认可的流程关系，局部修改不要擅自重做整套材料。
- 用户修改过的内容、布局和样式应保留。转换、修复工具默认生成新文件，已有输出使用新序号，避免覆盖原文件。
- 明确区分目标设计、已经实现的功能、Mock 示例、工程建议和待确认条件。不能将示意截图或 Mock 输出描述为真实运行数据。
- 如未在 PowerPoint 中实机检查，应如实说明验证范围；静态预览或命令行测试不等于已验证 PowerPoint 的全部编辑和弹窗行为。

## 本项目方案图的内容基线

以下属于当前项目的材料要求，不能机械套用到其他主题的 PPT：

- 当前三页分别为整体方案、GUI 通用方案、GUI 操作案例，不额外添加封面。
- 整体图的主要流程从左到右串联，大模块与内部流程分层表达；右侧约四分之一说明主要设计点与难点。
- GUI 通用页上半部保留已经确认的模块关系。下半部以开源框架对比表为主体，评测资料占较小区域。
- 框架背景说明来源团队和项目定位；三套框架的方法按相同维度逐行比较，另列优点、不足，不能各自介绍不同维度。
- 案例页以四块操作阶段展开，逐项说明 GUI 通用方案中同名模块在当前阶段做什么。
- 保持程序管理进度、上层规划每日活动、下层决定具体手机操作的边界。执行与逐图描述分别推进；计划与实际、虚拟与真实时间、原文与加工文本分别保存。

## 工程默认与检查建议

这些是实现默认，不是额外的用户硬性要求；用户模板和当前任务的明确要求优先：

- 新建常规宽屏演示可使用约 33.87 × 19.05 cm；保留本项目图示的 16:10 时，可使用约 33.87 × 21.17 cm。已有文件的尺寸按修改范围处理。
- 字体层级结合页面密度和用户模板确定，不把导出工具的默认字号当成固定规范。
- 渲染每一页检查文字换行、裁切、箭头路径和表格；检查段落与对象的对应关系，而非只数文字是否齐全。
- 导出检查应覆盖普通对象的组合锁定、原生表格、单个文本框中的完整段落、单对象折线与原生虚线。若工具不能直接生成，修复实际文件结构或更换实现方式，不能默默退回碎片拼接。
- 工具类交付要检查实际启动入口、缺少文件、错误退出和文件路径含中文、空格等情况。未实际测试的 GUI 入口需要注明，不能用后台参数测试替代交互验证。
