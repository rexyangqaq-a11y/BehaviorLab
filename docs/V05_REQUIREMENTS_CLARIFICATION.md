## 1. 状态与目标

本文的“已确认”来自用户既有指令与交接约定；“工程建议”是实现选择；“待确认”未获得用户答复。来源冲突时以最新用户指令和当前交接边界为准。例如MODEL_CALL_POLICY的2026-10-22恢复记录是历史授权，不覆盖本次暂停；VERSION_PLAN的“主选框架”按保留三框架、用户自行配置解释。

**已确认目标**：让主仿真调度中的一个手工／Mock上层活动进入用户所选下层执行适配器，保存有依据的实际进度、证据和停止原因；先完成无真实模型、无手机的离线装配与故障契约。

完成分三个层次：

| v0.5离线实现 | 统一装配、单活动调试、工作状态／对象台账、故障与兼容用例、对应界面入口验证 | 待实施 |

## 2. 范围与使用流程

包含：一个活动的手工输入或Mock计划、三框架可选择装配、模块来源与版本冻结、主系统和phone-lab设备排他、逐步证据、活动内对象去重、有限执行、暂停与恢复、阶段状态、单活动测试调试入口、导出兼容。

暂不包含：真实人设和上层规划、存档VLM、长期记忆、跨日多用户真实稳定性、跨APP／跨活动去重、百对象效果实验、视频断流修复、第二台物理电脑、正式部署包更新。hipyum资料不足不阻塞现有HDC路线。

建议流程：创建或选择任务→确认当前待执行活动→选择执行来源和组合→查看并冻结活动／配置→运行一个离线活动→查看实际结果、对象与证据→有终态则保存后反馈，无确定结果则停在`needs_attention`→按需补已有图的描述／导出。

手工活动仍须通过现有用户、虚拟日期、APP能力和计划版本校验；不能另建一条绕开主调度的临时phone-lab运行。单活动执行遵循已有顺序，筛选或指定ID不能跳过前序活动。已有结果只补缺失反馈，不重新采集。

## 4. 结果、计数与停止语义

计划目标与实际完成量分别保存。贯穿示例暂采用通用浏览：目标2，证据核实A，重复打开A，再无新对象，最终实际1。

| 状态 | 含义 | 后续行为 |
|---|---|---|
| completed | 达到对象目标，所需条件和全过程约束有核验依据，无未决效果 | 提交结果，再反馈 |
| partial | 有已核实对象，未达到全部目标或全部条件，停止原因明确，无未决效果 | 提交实际量和缺口，再反馈 |
| blocked | 无可计入成果，或存在使活动整体无效的明确阻断／禁止条件；保留已有事实及原因 | 提交结果，再反馈；不重试 |
| needs_attention | 发送／动作效果／证据或恢复状态无法确定；可能已有可核实成果 | 保存工作快照并停止调度；处理前不生成普通终态反馈 |

判断优先级建议：未决效果→明确硬性禁止／无效条件→目标与条件是否全部满足→有成果但不足→零成果受阻。实际量大于零并不排除blocked，例如已看到一个对象，但明确违反了任务全程硬性约束；原因和已有事实均须展示。工程错误另记阶段、错误码与原始原因，不把工程退出状态直接映射为业务完成。

计数单位建议限定为活动内的对象。可计数对象必须同时具备：可靠身份、满足条件的证据、达到本任务完成口径的证据。仅点击、截图张数、框架自报数量、命令返回和finish都不直接增加数量。身份未知／条件未知的对象保留为未核实；截图哈希相同或不同都不能单独证明业务对象相同或不同。

目标2／实际1且无未决效果的示例必须为partial；重复A仍为1。若随后有动作效果未知，则展示已核实1，同时状态为needs_attention。对后续人工补证据的处理不得覆盖先前轨迹或把未知时间段编造成已发生行为。

## 5. 恢复、人工处理与配置变化

设备控制的发送边界与数据库事务无法成为一个原子事务。即使意图已保存、未见返回，也不能推断动作未发送。只有可靠的发送前拒绝证据才能标记未发送；其他发送窗口中断先保守停止。

安全恢复需同时满足：原执行进程已停止、持有设备排他权、冻结快照匹配、证据链完整且未决项已消除、执行器明确支持从当前检查点继续。没有原生会话续接能力时不重跑整个自然语言目标，返回needs_attention即可。

人工交互的推荐范围为：查看未决动作和现有证据→记录已发生／未发生／仍未知及依据→单独选择继续／结束。用户明确标记“已发生”仅解决该动作效果，不自动证明业务对象完成。仍未知时保持阻断；结束时保留无法核实的说明，不能通过点击“结束”把未知改成partial或completed。保存意见不启动设备观察；额外观察也受当前暂停和预算约束。

恢复期间配置改变不得热更新原执行。新组合需新活动／运行及明确关联，旧事实留存；本版不需要为此实现复杂的活动分叉编辑器。凭据只保留引用；可发现的凭据修订变化应阻断原快照恢复，不能导出凭据值。

## 6. 离线验证用例

以下是本版待实现用例定义，**尚未执行，不能计入现有133项回归**。所有数据使用临时目录、合成图／固定回复、注入工具；不读历史私人轨迹作为必需输入。

| ID | 场景 | 必须观察到 |
|---|---|---|
| T01 | 三框架选择与默认推荐 | 三条注册装配分支被验证；用户选择保留，未知ID拒绝，无自动调用／绑定改写 |
| T02 | 冻结／恢复失配 | 任务、框架源、模型或工具配置改变均被识别；原运行不静默换组合 |
| T03 | 手工活动与Mock计划各派发一项 | 均经过同一调度；最多执行一活动，不绕序、不启动下一项 |
| T04 | 步骤／观察／原始回复记录 | 先落意图后工具调用，全部观察图按序关联，可回溯原文与解析 |
| T05 | 两Run、CLI／Web／phone-lab设备争用与暂停 | 同一共享锁只有一执行者；争用方零动作；父进程退出但worker仍活时不错误释放 |
| T06 | 2目标／1实际／重复A及2个独立合格对象 | 前者partial且实际1；后者completed且实际2；重复不累加 |
| T07 | 身份或条件未知、硬性禁止条件 | 未核实不计数；硬性约束失败不记completed；不伪造字段 |
| T08 | 无进展／步数／耗时／请求上限 | 按冻结界限停止；保留已知数量；无自动重试与换模型 |
| T09 | 意图前、意图后发送前、发送中、返回后核验前／后中断 | 已证明未发送与效果未知分开；不自动重放；已核实对象不重复计数 |
| T10 | 模型超时／格式错误、工具拒绝／超时 | 工程错误和业务结果分开；未知usage不记零；效果未知优先进入关注 |
| T11 | 描述失败后补跑 | 仅消费已有截图，采集次数与执行次数不增加 |
| T12 | 图像或台账／结果存储失败 | 不继续发动作，不伪造成功；重启能识别不完整提交；不可写时不声称已落盘 |
| T13 | 结果提交后反馈前中断 | 重启只补反馈；结果与对象不重复；关注状态不推进下一活动 |
| T14 | 本版任务内测试调试页面 | 实际入口、单活动控制、故障定位与阶段来源可操作；有GUI验证范围说明 |
| T15 | 旧Mock／旧导出／phone-lab回归 | 原Mock恢复正常；历史轨迹不改写；独立工作台继续可用 |
| T16 | 导出与不完整证据 | 能查看实际量、对象依据、阶段缺口与Mock来源，密钥不外泄 |
| T17 | 人工复核、重复提交与过期版本 | 意见有历史、版本冲突拒绝，复核零动作；只有符合恢复条件才允许显式继续 |

原生框架离线契约与以上装配测试分别报告。替身只能证明选择路径与工程语义；具备依赖时再验证实际原生入口，依赖缺失标明跳过。页面HTTP成功不能替代实际界面操作；离线界面操作也不是手机GUI效果评测。
