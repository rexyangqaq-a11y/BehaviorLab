# 版本开发协作流程

生效日期：2026-10-25。适用范围：本工作区后续版本开发，以及用户要求重新讨论的版本。依据：用户要求头脑风暴过程中持续确认，再做需求澄清与概要设计，并要求将此流程固化。具体阶段安排以用户最新明确指令为准。

## 1. 基本原则

先共同理解问题，再形成需求，再决定怎样实现。助手负责提出具体问题、提供建议与取舍、记录结论；用户确认业务口径、重要取舍和阶段推进。

“可以／好”等答复按其对应问题解释：确认一个计数规则不等于批准整套需求，确认可以整理需求不等于授权开始概要设计。无需指定固定审批词；答复的上下文清楚即可。已有明确跨阶段授权时直接按授权推进，不把流程变成重复请示。

每份材料区分：用户已确认、历史交接约束、工程建议、待讨论、已经实现和已经验证。建议不能自动升级为已确认，离线验证不能升级为真实效果成绩。

## 2. 阶段与推进条件

| 阶段 | 助手应做什么 | 推进条件与下一步 |
|---|---|---|
| 0 启动与基线 | 读取AGENTS、README、CURRENT_STATUS、NEXT_TASK及相关约束；检查Git和指定基线，保留已有改动 | 明确本轮目标和当前授权范围；有指定基线时据此开始 |
| 1 头脑风暴 | 与用户逐轮讨论场景、成功口径、边界、异常和自主程度；每轮聚焦一个关键问题或少量相关问题 | 关键业务问题已讨论后，汇总全部结论与剩余问题，请用户确认能否收敛进入需求 |
| 2 需求澄清 | 根据已确认结论整理业务流程、需求、验收场景、约束与待定参数；避免提前决定内部技术结构 | 交用户核对需求；调整后在用户明确确认进入设计时，再写概要设计 |
| 3 概要设计 | 依据已确认需求整理模块职责、执行与恢复流程、数据关系、接口边界、取舍及验证安排 | 交用户核对主要方案；按用户对设计和实施的明确授权进入实现 |
| 4 实现与验证 | 在已确认边界内自主完成代码、必要测试、版本调试入口、证据和回归；重大业务变化先回到讨论 | 完成约定验证，列出真实能力、Mock、未完成与未验证范围，交付本地提交 |
| 5 交接与后续 | 更新当前状态、唯一下一步、源码／部署差异、使用方法与本地回退入口 | 实际达到完成条件才称本阶段／版本完成；后续版本重新核对范围 |

用户可以明确合并阶段、直接授权多阶段工作，或把已确认议题重新打开。助手按最新授权执行；普通技术细节、可逆调整、文档校对和已授权测试无需逐条请示。

## 3. 头脑风暴的记录方式

记录应能回答：讨论了什么、用户确认了什么、哪些是助手建议、哪些仍未知、当前允许推进到哪里。先用自然语言和具体例子解释，用户不理解时继续解释当前问题，不把提问当成同意，也不立即转到下一议题。

用户对一个议题的补充通常修正该议题，已确认的其他结论继续有效。例如“从手机首页开始”应修正活动起点，不能丢失此前确认的计数与去重规则。用户明确要求重新开始时，先说明哪些结论保留、哪些稿件暂停采用，再继续共同讨论。

阶段收敛时提供简短汇总及尚未决定的事项。非关键参数可标待细化；影响目标、真实性或安全继续条件的问题不能用默认值掩盖。

## 4. 文档与状态管理

每个版本可采用以下文件，沿用既有名称时不强制另建：

- `Vxx_BRAINSTORM.md`：已确认结论、讨论来源、尚未决定的问题及收敛状态。
- `Vxx_REQUIREMENTS_CLARIFICATION.md`：待核对／已确认的需求、验收场景、范围与参数。
- `Vxx_HIGH_LEVEL_DESIGN.md`：待核对／已确认的概要设计；仅在进入该阶段后编写或更新实质方案。

标题或首段必须标明阶段和状态。若先前越阶段生成材料，保留Git历史，在文件顶部明确“暂停采用”，不继续润色其方案，也不以其作为当前实施指令。用户确认需求后，再基于最新需求重新整理设计。

CURRENT_STATUS记录当前事实；NEXT_TASK只指向当前阶段的下一步，不能在需求待核对时指向开始编码。只固化流程或修订文档状态，不代表用户批准了正文中的全部需求和设计。

## 5. 验证、Git和真实执行

沿用[随版测试要求](VERSION_TEST_PLAN.md)：版本实现应有对应的独立用例与测试调试界面，并验证实际入口。文档阶段检查链接、内容一致性和差异即可；不为了文档提交无故重跑全量工程测试。

每轮源码、测试或文档改动验证后提交本地Git；检查暂存范围，不包含密钥、运行库、原始截图、依赖和输出包。进行中的保存点标WIP，不宣称功能完成；不改写既有提交，不配置远程、不推送。

流程推进不自动恢复暂停的手机、真实模型、旧队列、视频或外部发布。真实调用及其预算按当前有效授权执行，历史批次授权不继承到新版本。工程回归、原生框架离线契约、网页实际操作、真实GUI效果分别报告。

## 6. v0.5当前应用

用户已逐项确认商品浏览等需求，针对“确认需求并进入概要设计”的提问答复“进入”；后续复核版本计划，确认v0.5下层接整体流程、v0.6真实上层、v0.7存档VLM的顺序，并补充具体活动不固化。用户核对概要设计与离线实施范围后答复“继续”，当前阶段为**实现与验证**，首轮离线接入已完成工程回归及网页入口核对，真实框架会话桥接／续接仍待补齐。无需重复索取已获得的阶段授权；手机与真实模型继续暂停。具体事实见[当前状态](CURRENT_STATUS.md)和[下一任务](NEXT_TASK.md)。
