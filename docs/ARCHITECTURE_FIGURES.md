## 1. 整体方案

上方保留六个大模块。下方改为从左到右相连的运行流程，取消六列等高步骤框。

1. 准备任务：生成用户候选、人工确认、固定人设，再选择APP、周期、虚拟时间和运行参数，校验后启动。
2. 执行当天活动：程序推进用户和虚拟日期，上层生成当天计划，下层逐项执行，保存实际结果后调整剩余活动。
3. 截图生成文字：每张原图和动作都保留；活动结束后按顺序生成观察文字，原文与加工文本分别保存，再按用户、时间和步骤导出。

图中紫线表示实际结果反馈给规划，蓝线表示手机操作产生的截图进入描述流程。两线交叉处没有连接点，不表示反馈必须等待描述。下一活动可以与上一活动的逐图描述同时进行。

程序管理进度，上层决定做什么，下层决定手机怎么操作。每个用户只带入自己的相关记录；计划与实际、虚拟与真实时间、原文与加工文本分别保存。右侧保留主要设计点与难点。

“记忆生成”指供研究使用的逐图观察文字，不包含下游的记忆提取、融合和检索。

## 2. GUI通用方案

上半部沿用第一版的模块关系：上层活动要求与当前活动记录进入下层执行Agent，六个模块构成操作循环；右侧保留模型服务和可选操作复用的连线。整体方案图沿用上一版。

| 模块 | 读取什么、做什么、交出什么 |
|---|---|
| ① 子任务规划 | 读取活动要求和当前进度，写明当前子任务的开始条件、完成条件；执行结果变化时只修改受影响的步骤 |
| ② 页面观察与定位 | 读取截图和可用UI信息，识别页面内容、对象与按钮位置；位置绑定当前截图ID、尺寸与方向 |
| ③ 动作选择与检查 | 结合子任务、新页面和已完成步骤，提出动作、参数、目的和预期变化；检查APP、定位、步数与预算 |
| ④ 手机接口与操作 | 先保存准备执行的动作，再通过hipyum点击、输入或滑动，取得调用结果、错误与新截图 |
| ⑤ 操作结果核对 | 比较前后页面、调用结果与预期，核对对象数量和限制，给出成功、失败或未知及其依据 |
| ⑥ 进度更新与结束判断 | 不同对象分别计数，保存子任务状态与实际完成量；无进展时调整当前步骤或结束，结果不确定先查状态 |

活动结束时，无论完成、部分完成还是受阻，都返回实际数量、原因及对应截图。外层保存后，上层再调整当天剩余活动。执行和逐图描述分别推进。

六个模块是职责划分，不要求各用一个模型服务，也不要求每个阶段固定调用模型六次。具体操作需要多次观察、选择与核对；模块如何合并调用可以在接入后比较效果和成本。

模型分工为建议：内网DeepSeek V4或外网GLM-5.2负责文字规划和下一步判断，Qwen多模态负责看图、定位与核对。GLM-5.2的[官方规格为文本输入](https://docs.z.ai/guides/llm/glm-5.2)。全内网运行仍需可用视觉模型，截图是否可以传到外网、服务版本和预算按实际部署确认。

右侧操作复用为可选：为搜索、筛选、详情和返回等重复步骤写明页面条件、参数与结束依据，再用成功步骤验证；页面不匹配时退出，回到逐步判断。图示没有要求先建行为库。

## 3. 开源框架与评测资料

图中下半部分以表格对比三套开源框架。背景一行说明来源团队和项目定位；做法按任务规划、页面观察、动作执行、核对纠错、信息复用五个相同维度逐行比较，最后列优点与不足。它们提供的模型、执行循环和轨迹存储并不完全相同，不能把单个手机操作API算作完整Agent。

| 对比项 | [Open-AutoGLM](https://github.com/zai-org/Open-AutoGLM) | [Mobile-Agent-v3](https://arxiv.org/html/2508.15144v2) | [AppAgentX](https://appagentx.github.io/) |
|---|---|---|---|
| 背景来源 | 智谱/Z.ai开源的手机Agent项目；<br>配套AutoGLM-Phone，面向手机APP。 | 阿里通义团队的GUI Agent研究项目；<br>GUI-Owl模型支撑手机与桌面操作。 | 西湖大学等团队的GUI Agent研究项目；<br>关注重复任务的效率与操作复用。 |
| 任务规划 | 同一模型逐步决定下一动作 | 规划角色列子任务并按反馈修订 | 依据目标与已有轨迹选择可用操作 |
| 页面观察 | 当前截图与当前APP信息 | 执行角色读取当前页面与已存要点 | OmniParser标注元素，匹配历史节点 |
| 动作执行 | 解析模型动作，经设备接口执行 | 执行角色经设备接口完成当前动作 | 基础动作，或匹配的高层操作 |
| 核对纠错 | 重看新截图；模型报告完成或步数到限 | 核对角色比较前后页面，反馈给规划 | 页面匹配或执行异常时退回基础动作 |
| 信息复用 | 会话历史；基本循环未单列技能检索 | 临时要点记录，外部知识检索 | 轨迹存成链，重复步骤归纳成快捷操作 |
| 优点 | 单步循环简单，模型和设备接口可换；<br>便于先验证基本手机操作。 | 子任务、执行与核对分工清楚；<br>便于跟踪复杂任务的进展与失败。 | 重复流程可合并，减少逐步推理次数；<br>稳定页面上的重复任务可能更省时。 |
| 不足 | 长任务的状态与成功核对需额外设计；<br>不能直接当作本项目完整下层Agent。 | 多角色调用可能增加延迟与调试量；<br>需控制错误反馈对后续步骤的影响。 | 依赖轨迹质量及页面匹配；<br>需维护存储、技能条件与失效处理。 |

背景与方法依据项目官方资料：[Open-AutoGLM项目与配套模型](https://github.com/zai-org/Open-AutoGLM)、[其基本执行循环](https://github.com/zai-org/Open-AutoGLM/blob/main/phone_agent/agent.py)、[Mobile-Agent-v3论文与作者单位](https://arxiv.org/html/2508.15144v2)、[AppAgentX作者项目页](https://appagentx.github.io/)、[AppAgentX论文](https://arxiv.org/html/2503.02268)。其中，Open-AutoGLM的“未单列技能检索”限定于所查看的基本执行循环；AppAgentX的高层操作依赖页面匹配与任务条件，不是无条件回放动作。

优缺点是据公开结构、依赖与本项目场景作出的工程判断，不是实测排名，也不表示已经集成。框架表占下半页主体，评测资料仍放在右侧较小区域。操作复用仍是可选方案，没有要求先建设行为库。

| 评测环境或数据 | 提供什么 | 能测什么与使用限制 |
|---|---|---|
| [AndroidWorld](https://github.com/google-research/android_world) | 在线Android模拟器环境，20个APP、116个参数化任务，支持初始化与状态检查 | 适合测试完整任务执行以及可重复的成功判断。任务内容和APP覆盖有限；不能据此保证大众点评、携程等商业APP可用，也不能评估本项目的长期人设一致性 |
| [AITW](https://github.com/google-research/google-research/tree/master/android_in_the_wild) | 人工采集的指令、截图、动作轨迹，提供离线动作匹配方法 | 可比较动作类型、点击位置和滑动方向，排查页面理解和动作选择问题；匹配示范动作不证明真实手机能从头完成任务 |
| [AndroidControl](https://github.com/google-research/google-research/tree/master/android_control) | 真人演示的整项任务目标、步骤指令、截图、UI树和JSON动作 | 可分开比较“从任务目标选动作”和“给定步骤指令做操作”，帮助区分规划与执行问题。一条步骤说明可能需要多次动作，不能当成固定的一步一按钮脚本；它仍是离线数据 |

最后仍需在选定的商业APP上自建任务，检查是否完成、是否满足数量和条件、是否重复计数、卡在哪里，以及耗时和模型调用次数。这里不引用公开榜单成绩作为本项目的效果承诺。

资料核查日期：2026-10-19。除上述链接外，AppAgentX方法说明见[作者项目页](https://appagentx.github.io/)。

## 4. 四块操作示例与模块对应

第三页沿用搜索、选店、查看详情与评价、收藏确认四块。每块下方使用与通用方案完全相同的①至⑥模块编号，说明当前阶段的信息、选择、操作、核对和进度。

示例目标：在杭州西湖区找2家人均不超过150元的杭帮菜，查看地址和近期评价后收藏，偏好口味清淡。A为92元，B为188元，C为128元；先完成A，跳过超预算的B，再回到第2块继续C。

| 模块 | 搜索杭帮菜 | 选择候选餐厅 | 查看详情与评价 | 收藏并确认 |
|---|---|---|---|---|
| ① 子任务规划 | 搜索后，逐店核对并收藏2家。 | 先找一家未查看、未超预算的店。 | 查齐区域、人均和近期评价。 | 收藏当前餐厅，并核对完成数量。 |
| ② 页面观察与定位 | 识别当前城市和搜索框的位置。 | 读出A92元、B188元、C128元。 | 看到西湖区、92元、口味清淡。 | 定位收藏按钮，读取操作后状态。 |
| ③ 动作选择与检查 | 关键词固定为“杭帮菜”。 | 跳过B；先选A，C留待下一家。 | 当前条件满足，决定进入收藏。 | 未收藏才点击；已收藏不重复点。 |
| ④ 手机接口与操作 | 点按、输入、提交；每步截图。 | 点A，取得详情页截图。 | 滑动并打开评价，保存截图。 | hipyum点击收藏，重新截图。 |
| ⑤ 操作结果核对 | 确认列表显示“杭帮菜·西湖区”。 | 核对详情页店名为A。 | 缺信息继续查，不符合则换店。 | 出现“已收藏”才计为成功。 |
| ⑥ 进度更新与结束判断 | 已收藏0/2，进入候选筛选。 | A正在查看，C待看；收藏0/2。 | 保存A的查看结果，准备收藏。 | 确认A为1/2；回列表继续看C。 |


图中当前画面停在A已收藏、完成1/2家；紫色返回线表示继续查看C，底部结果条表示重复第2至第4块后返回A与C、完成2/2家。当前画面和最终结果不是同一个时刻。

**所有页面、餐厅、价格、评价和结果均为Mock示意**，不是实机截图或真实数据。详情与评价合并展示；每块也合并了若干真实操作，实际每一步都重新截图、判断。数量不足就返回实际，不改区域或预算，不重复计数。
