## 当前用例与轨迹

启动单项测试或组合评估后自动进入“测试过程详情”，跟随当前正在执行的用例。页内显示执行时冻结的名称、任务版本、框架/模型、手机型号、起点、任务要求、禁止操作与限额。模型请求、框架动作、执行段耗时、已知 tokens 分别统计，不把请求数等同于动作数。

轨迹每秒读取已有 JSONL 记录，按游标增量传输；不会为展示额外请求模型或截取手机屏幕。模型步骤包含原始判断字段、完整回复、实际提交的图像引用和关联动作；动作步骤包含参数、返回/未知状态、动作期间的 HDC 日志和前后图。读取到尚未写完的一行时，下一次刷新继续读取，不补写回复。

默认跟随最新步骤；点击旧步骤会暂停跟随，避免阅读时跳走，“跟随最新”可恢复。结果页与过程页的选择状态独立。结束后本页保留刚查看的用例，明确显示等待业务核对；点击“前往结果与判定”复核，框架结束或动作返回均不自动判通过。新打开且空闲的过程页不会将旧历史标成正在测试。

## 连续投屏方案已撤回

用户2026-10-23明确要求避免打开官方工具，当前依赖 DevEco Testing 窗口和浏览器选窗的实现已回退。页面不再有投屏窗口、选窗或启动官方工具的按钮；后台启动接口、窗口采集代码与相应媒体策略已移除。当前步骤中显示的是执行时留存的证据图，不标为连续视频，不新增截图循环。

技术上存在不依赖桌面工具窗口的路线：[HOScrcpy 原项目](https://gitcode.com/OpenHarmonyToolkitsPlaza/HOScrcpy)公开说明了视频采集 API、独立 SDK 和通过本地 WebSocket 在 HTML 展示 H.264 的示例。它是待验证候选，不是本项目已经部署的能力；仓库说明要求另外取得对应 SDK JAR。本次没有安装该 SDK、启动手机端采集扩展，或把录屏文件冒充实时视频。

后续若推进直接视频，最少需要确认兼容当前手机系统的采集 SDK/扩展版本、本机后台接收和网页解码链路、与三框架同时运行时的资源占用及停止回收。可选路线不能以存在 README 或网页示例代替真机验证。本轮只读 HDC 设备列表确认1台可见，不操作手机页面、不调用模型。
