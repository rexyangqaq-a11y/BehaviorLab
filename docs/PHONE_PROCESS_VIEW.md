# 测试过程详情与连续视频

2026-10-23，0.4.0-preview.7。本机入口：<http://127.0.0.1:4317/phone-lab#process>。

## 当前用例与轨迹

启动单项测试或组合评估后自动进入“测试过程详情”，跟随当前正在执行的用例。页内显示执行时冻结的名称、任务版本、框架/模型、手机型号、起点、任务要求、禁止操作与限额。模型请求、框架动作、执行段耗时、已知 tokens 分别统计，不把请求数等同于动作数。

轨迹每秒读取已有 JSONL 记录，按游标增量传输；不会为展示额外请求模型或截取手机屏幕。模型步骤包含原始判断字段、完整回复、实际提交的图像引用和关联动作；动作步骤包含参数、返回/未知状态、动作期间的 HDC 日志和前后图。读取到尚未写完的一行时，下一次刷新继续读取，不补写回复。

默认跟随最新步骤；点击旧步骤会暂停跟随，避免阅读时跳走，“跟随最新”可恢复。结果页与过程页的选择状态独立。结束后本页保留刚查看的用例，明确显示等待业务核对；点击“前往结果与判定”复核，框架结束或动作返回均不自动判通过。新打开且空闲的过程页不会将旧历史标成正在测试。

## 连续视频接入

使用官方 DevEco Testing 的设备投屏窗口作为来源，通过浏览器 `getDisplayMedia` 接入网页 `<video>`。这是窗口的连续 MediaStream，不是历史执行截图轮播，也不是直接解码 HDC 视频。网页只能核对已收到窗口视频帧，无法据此证明窗口内的手机已经连接；手机连接状态由官方工具显示。

1. 手机 USB 连接，解锁并允许调试；在 DevEco Testing 中开启“实用工具 → 设备投屏”。网页“打开官方工具”仅显式请求启动本机已安装程序，不自动选择设备或操作手机。
2. 推荐在 Edge 或 Chrome 打开上述本机页面，点击“接入投屏窗口”，在浏览器选择器中选择官方投屏窗口。浏览器不允许网页自动指定某个窗口，也不持久保存选窗权限，见 [Chrome 官方说明](https://developer.chrome.com/docs/web-platform/screen-sharing-controls)。内置浏览器若未弹出选择器或不支持共享，改用 Edge/Chrome。
3. 确认网页出现手机画面和视频帧计数。可以全屏查看；缩小、遮挡或最小化投屏窗口可能影响系统提供的视频帧，需保持来源窗口可用。
4. 点击“断开”、关闭共享窗口或离开过程页会停止浏览器流；页面卸载也会释放 tracks。选窗未完成时离开页面，迟到返回的流会立即释放。原生选择器若仍在，请在选择器中取消。

本功能关闭音频，不使用录制、远端连接或上传接口。视频只在当前浏览器本机播放，不进入测试证据包；历史回放仍依靠实际执行截图与日志。投屏工具和 USB 带来的系统影响没有做定量性能校准，不能声称对真机耗时完全无影响。

## 代码入口与验证边界

| 入口 | 职责 |
|---|---|
| `src/phone-lab.mjs#processSnapshot` | 只读轨迹游标、状态与冻结输入 |
| `src/phone-mirroring.mjs` | 检测/显式启动已配置的官方工具，不接收任意命令 |
| `web/phone-process.mjs` | 轨迹投影、关联证据、视频会话生命周期 |
| `web/phone-process-ui.mjs` | 当前用例、轮询、稳定 video 节点与帧状态展示 |
| `tests/phone-process.test.mjs` | 临时数据/替身轨道的协议与生命周期回归 |

最少实机条件：已授权且解锁的 USB 手机、官方工具内可见的投屏窗口、支持窗口共享的浏览器，以及用户在浏览器中手动选窗。本机已检测到 DevEco Testing。工程回归与浏览器夹具验收不替代这一步；本轮未新增模型或手机任务，连续手机视频实机验证待用户选窗。验收范围见 [acceptance.json](evidence/20261023-phone-process/acceptance.json)。

本版源码已更新，2026-10-22 的干净部署 ZIP 仍为 preview.6，不含新增页签，也不包含 DevEco Testing。后续打包会按新源码收集 `web/`、`src/` 文件；另一台电脑须自行安装官方投屏工具并连接手机。
